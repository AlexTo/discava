## 共同概念

**课程结构层级。** 课程包含模块，模块包含课时，课时包含一个有序的内容项列表（视频、文本、文件、测验、作业）。这四者都通过 ElectroDB 的 `curriculum` 集合存放在同一个 DynamoDB 分区（`COURSE#<courseId>`）中，因此整门课程只需一次查询。该查询会读取每一页，因为课程的课程结构可能超过 DynamoDB 每页 1 MB 的限制。

**有效可见性。** 只有当模块、课时或内容项**及其所有祖先**都是 `visible` 且未归档时，才会向学生显示。学生读取、学生写入和进度计算都使用有效可见性，而不是只看记录自身的 `visibility`。该规则只实现了一次，即 `@discava/core-table` 中的 `filterEffectivelyVisible`。

**选课。** 学生只有在已选课期间，才能读取课程内容并写入其中的任何数据：他们拥有一条 `enrolment` 记录（pk `courseId`，sk `userId`），其 `status` 不是 `dropped`。学生通过 core-api 的 `course.enrol` 自行选课，且只能选**已发布**的**免费**课程：课程的状态和价格会与选课写入在同一个事务中检查，因此请求过程中被归档或被定价的课程无法接受新的选课。有价格的课程只能通过已付款的订单进入（见<Link path="design/payments">支付</Link>）。再次选课会返回已有的选课记录。草稿或已归档的课程会返回 `NOT_FOUND`，与匿名的 `course.publicView` 一致，因此不会泄露草稿的存在。已选课的学生在课程被归档之后仍可阅读，但对他们来说也是只读的。`course.myEnrolment` 返回调用者的选课记录，如果没有则返回空。

**学生数据以用户为键。** `progress`、`itemCompletion`、`quizAttempt` 和 `quizSummary` 使用 `userId` 作为分区键，因此"某位学生在某门课程中的进度"只需一次查询。反过来说，"哪些学生接触过这个内容项？"不做扫描就无法回答，这就是内容项带有 `studentActivityCount` 的原因。
