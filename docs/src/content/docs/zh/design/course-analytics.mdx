讲师门户的仪表板为每门课程显示一张摘要卡片，每张卡片会打开该课程的分析页面。两者读取的都是已存储的数据，这些数据由核心表的流持续更新。请求时不会从记录中重新统计，因此无论有多少学生报名，页面都能快速加载。

门户通过 instructor-api 的 `analytics.courseSummaries`（卡片）、`analytics.course`、`analytics.quiz` 和 `analytics.videoQuestions` 读取这些数据。

## 定义

| 指标 | 定义 |
|---|---|
| **报名数（Enrolments）** | 课程有过的所有报名，包括已退出的学生。历史图表按学生报名当天的 UTC 日期计数 |
| **已退出（Dropped）** | 状态为 dropped 的报名。它们保留在报名历史中，但不计入下面的其他所有指标 |
| **活跃学习者** | 完成过某个学习项（包括提交作业）、提交过测验作答或回答过视频问题的已报名学生。登录或打开页面不算，因为这两者都没有记录 |
| **本周活跃** | 当前自然周（周一至周日，UTC）内不重复的活跃学习者。分析页面还会显示最近 30 天或 90 天内每个 UTC 日的不重复活跃学习者 |
| **完成率** | 已完成的报名数除以所有未退出的报名数。没有此类报名的课程显示“No data”，而不是 0% |
| **已激活（Activated）** | 在课程中做过第一件事的报名：该报名有最后活动时间，由第一个完成的学习项、测验作答、作业提交或视频问题回答设置。所有报名都计入，包括已结束的。它根据报名的最后活动时间统计，因此不会另存新标记，并且是“截至目前”的：尚未开始的学习者之后仍可能被激活。历史图表将其归入学生报名当天的 UTC 日期 |
| **激活率** | 已激活的报名数除以所有报名数，两者都包括已结束的报名。显示全部时间的数据，以及最近 30 天或 90 天内报名的学习者的数据。没有报名的课程显示“No data”，而不是 0% |
| **提示回答与关闭** | 有多少学习者回答了首节课提示，有多少按下了 **Not now**。每位学习者在每门课程中只计一次。提示被显示了多少次没有记录，因此没有比率 |
| **流失（Drop-off）** | 对当前向学生显示的每节课，按课程顺序：有多少学习者开始、有多少完成，以及完成人数占开始人数的比例。隐藏或归档的课，以及隐藏或归档模块中的课，不包括在内 |
| **分数段** | 每位学生每个测验的最高分，按十分一段（0-9、10-19 ... 90-100）划分，因此无论作答多少次，一名学生只计一次 |
| **最常答错的问题** | 按所有作答中的答错率排序。问题至少需要 5 次作答才会参与排名，这样一次糟糕的作答不会让它排在第一 |
| **视频问题结果** | 对每个向学生显示且含有问题的视频，以及每个当前问题：它出现的时间点（或“End of video”）、提示的开头、有多少学习者回答、有多少答错，以及答错率，排序方式与测验问题相同，同样要求至少 5 次回答。只计每位学习者第一次记录的回答：**Try again** 和跳过都不会被记录。已删除的问题不列出。结果中不含学习者标识 |
| **没有问题的模块** | 课程流失视图还会列出每个向学生显示的模块：它有已显示的视频，但没有已显示的测验，也没有带问题的已显示视频，并建议讲师添加一些。它读取当前课程大纲，因此不是计数，也不会出现偏差 |

## 新鲜度

这些数据比记录晚几秒，与课程进度相同。一项变化（报名、完成、测验作答）通常会在 30 秒内的下一次加载时显示。卡片和分析页面都会显示数据最后更新的时间。

## 数据如何维护

`analytics-update` 处理器是一项<Link path="design/stream-event-router">流事件路由器</Link>功能。它在五种核心表记录中保存计数器：`courseStats`、`periodStats`、`lessonStats`、`quizScoreStats` 和 `quizQuestionStats`。

- **每项变化只计一次。** 一项变化的计数与一个以流记录命名的 `analyticsMarker` 在同一个事务中写入。重复投递的记录会发现它的标记，不会再计数。
- **每位学习者每天、每周只计一次。** 每位学习者每个时间段的第二个标记，使“活跃”成为不重复学习者的计数。
- **顺序无关紧要。** 计数器只会增加，而一节课的流失数据根据学生当前的记录确定，而不是根据到达的那项变化。

如果这些数据与记录出现偏差，`analytics-matches-records` 不变量会发现它，而 `pnpm nx run @discava/tooling-deploy:rebuild-analytics -- <courseId>` 会根据记录重新计算一门课程的数据。
