## 谁能做什么

访问权限分层决定，每一层都假设前一层可能失效。

| 层 | 强制执行的内容 |
| --- | --- |
| **Cognito 用户组** | 用户的角色：`student`、`instructor` 或 `admin` |
| **独立的 API** | 讲师和管理员的过程是独立的部署。学生的令牌在任何过程运行之前就会被 instructor-api 拒绝 |
| **过程规则** | 具体的规则：这位讲师拥有这门课程，这位学生已报名该课程 |
| **签名媒体** | 视频或文件只提供给为其签名的请求。签名在访问检查（例如报名情况）之后签发 |

对不该看到草稿或已归档课程的人，它会返回“未找到”，因此不会暴露它的存在。

## 每个 stage 的保护

每项保护都**默认开启**。stage 的配置只能关闭某些保护，`discava-development` 就是这样做来节省成本的。

| 保护 | 作用 | 生产 | 开发 |
| --- | --- | --- | --- |
| **WAF** | 用于门户、API、媒体和用户池的 Web 应用防火墙 | 开 | 关 |
| **KMS 加密** | 客户管理的密钥（带轮换），用于表、存储桶、队列、日志和搜索 | 开 | 关（使用 AWS 管理的加密） |
| **MFA** | 登录时的第二因素 | 开 | 关 |
| **删除保护** | 拒绝删除用户池和表 | 开 | 关 |
| **删除时保留** | 堆栈被移除时保留数据 | 开 | 关 |
| **自助注册** | 允许任何人创建账号 | 开 | 关 |
| **追踪** | 用 X-Ray 进行请求追踪 | 开 | 关 |

数据在静态存储和传输中始终是加密的。KMS 设置决定的是密钥是否由你控制和审计。

在关闭 WAF 的开发 stage 上，stage 配置中的请求限制、函数并发数和表吞吐量上限，决定了大量请求涌入时可能产生的成本。关闭自助注册后，外部人员无法获得账号去访问需要登录的过程。

## 系统内部的最小权限

- 每个 Lambda 函数都有自己的角色，只拥有其工作所需的权限。
- 敏感能力被隔离在专用函数中。签名课程媒体请求的密钥，只有 core-api 中的一个函数和 instructor-api 中的一个函数可以读取，处理其他所有过程的函数不能读取。
- Stripe 密钥和 webhook 签名密钥保存在 Secrets Manager 中。只有一个 admin-api 函数可以写入。结账、webhook、结算账户和结算运行函数只读取它们需要的内容，任何响应、日志行或审计记录都不包含这两者。
- Stripe webhook 只有在签名能通过已保存的签名密钥验证时才接受消息。付款结果从不信任浏览器。
- 没有任何 S3 存储桶是公开的。门户和媒体只能通过它们的 CloudFront 分发访问。
- 页面渲染函数以对表的只读权限提供公开页面，并且只有学生门户的 CloudFront 分发可以调用它。
- 每个 API 只响应来自调用它的门户的跨域请求：core-api 允许全部三个，instructor-api 允许讲师门户，admin-api 允许管理员门户。本地开发地址同样被允许。
- 搜索索引只由索引函数写入。API 只能读取。
- 函数通过部署时的环境变量获取资源名称，凭据从不出现在代码或环境文件中。

## 代码部署前的检查

| 检查 | 位置 | 发现的问题 |
| --- | --- | --- |
| **Checkov** | 每次构建 | 生成的模板中不安全的基础设施设置 |
| **Trivy** | CI 以及每次部署前 | 依赖中已知的漏洞，以及已提交的密钥 |
| **git-secrets** | 每次提交前 | 即将被提交的凭据 |
| **表不变量** | 端到端测试 | 数据处于违反跨多条记录规则的状态 |

## 把部署控制在范围之内

部署流水线本身也是攻击面，所以要对它加以约束：

- **不保存 AWS 凭据。** GitHub Actions 使用为单次运行签发的令牌登录。
- **部署角色只信任一个仓库的一个环境。** 为该环境设置必需的审批人，就可以为部署把关。
- **部署角色不能创建资源。** 它只能请求 CloudFormation 部署以其 stage 命名的堆栈。
- **执行角色的范围** 按名称限定在该 stage 的资源内。
- **权限边界** 限制 stage 创建的每个角色，所以部署的变更不能给自己授予超出边界的权限。

登录方式和这两个角色见 <Link path="deploy/ci-cd">CI/CD 参考</Link>。
