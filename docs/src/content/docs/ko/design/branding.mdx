관리자는 관리자 포털에서 로고, 이름, 아이콘, 공유 이미지, 색상을 설정하며, 모든 포털과 공개 페이지는 배포 없이 5분 안에 이를 반영합니다. 이 페이지는 그 동작 방식을 설명합니다.

## 레코드와 리비전

브랜드는 core 테이블의 `platformBrand` 레코드 하나이며 키는 상수입니다. 첫 저장 전에는 레코드가 없고, 없으면 기본 브랜드를 뜻합니다. `helpers/platform-brand.ts`의 `saveBrand`가 유일한 작성자입니다.

저장할 때마다 브랜드 전체와 관리자가 불러온 `revision`을 함께 보냅니다.

- 첫 저장은 레코드가 존재하지 않는 것을 조건으로 하고, 이후 저장은 `revision`이 불러온 값 그대로인 것을 조건으로 합니다.
- 조건이 실패하면 `CONFLICT`("Someone else changed the branding. Reload to see their changes.")가 되므로, 오래된 저장이 절반만 적용되는 일은 없습니다.
- `changedBy`, `changedByName`, `changedAt` 필드는 마지막으로 저장한 사람을 나타냅니다.

## 이미지와 불변 키

이미지는 공개 미디어 버킷의 `brand/<kind>/<nonce>.<ext>` 아래에 있으며, `kind`는 `logo`, `icon`, `share-image` 중 하나입니다. `branding.createUploadUrl`은 정확한 콘텐츠 타입과 길이, 1년짜리 불변 `Cache-Control`, `lifecycle=unattached` 태그를 지정한 `PUT`을 미리 서명합니다. 새 업로드는 새 키가 되므로, 브랜드가 다른 이미지를 가리킨 뒤에는 교체된 이미지가 캐시에서 제공되는 일이 없습니다.

`branding.save`는 새로 참조된 각 객체를 읽어 `@discava/common-branding/image-rules`의 규칙(관리자 포털도 업로드 전에 같은 규칙을 실행합니다)에 따라 형식, 크기, 형태를 검사합니다. 유지하는 객체에서는 태그를 제거하고, 교체된 객체에는 태그를 다시 붙이며, 버킷의 수명 주기 규칙이 하루 뒤 이를 삭제합니다. 이미지 하나라도 실패하면 아무것도 기록하지 않습니다.

### SVG 검사

SVG 로고는 파싱되며(admin-api의 `helpers/brand-image.ts`), 모든 요소와 속성이 허용 목록에 있지 않으면 거부됩니다. `script`, `foreignObject`, `iframe`, 이벤트 핸들러 속성, 같은 문서 내 `#fragment` 이외의 참조는 허용되지 않습니다. 고쳐 쓰지 않고 거부하므로 저장된 파일은 업로드된 것과 정확히 같습니다. 로고는 브라우저가 SVG 스크립트를 실행하지 않는 `<img>`로 표시되며, 파일을 직접 열 때를 위해 배포는 `sandbox`가 있는 `Content-Security-Policy`를 추가합니다. iOS 홈 화면 아이콘은 래스터여야 하므로 아이콘은 PNG만 허용합니다.

## 게시 문서

브라우저는 테이블을 읽지 않습니다. `brand-publishing` 스트림 기능([라우터](./stream-event-router/) 참고)은 스트림 이미지가 아니라 현재 레코드를 읽으므로, 늦게 도착한 전달이 이전 리비전을 게시할 수 없습니다. 이 기능은 공개 미디어 버킷에 `brand/brand.json`을 `Cache-Control: public, max-age=60, s-maxage=240`으로 넣습니다. 문서에는 누가 언제 저장했는지가 빠져 있습니다. 포털은 다른 출처에서 이를 가져오므로, 배포는 `brand/` 아래 모든 것에 `GET`과 `HEAD`용 CORS 헤더를 추가합니다.

이것이 **캐시 예산**입니다. 브라우저는 문서를 최대 60초, CloudFront는 최대 240초 보관하므로, 변경은 5분 안에 모든 새 페이지 로드에 반영됩니다. 문서가 없거나 읽을 수 없거나 유효하지 않으면 기본 브랜드를 뜻하므로, 실패가 페이지를 깨뜨리지 않습니다.

## 포털에서

`@discava/common-web-utils/brand`의 `BrandProvider`는 각 포털의 `RuntimeConfigProvider` 안쪽에 있으며, `useBrand()`는 확정된 브랜드를 제공합니다. 시작할 때는 페이지 렌더러가 포함시킨 브랜드를 쓰고, 없으면 마지막으로 본 브랜드(`localStorage`에 보관), 그것도 없으면 아무것도 쓰지 않습니다. 브랜드가 있으면 즉시 렌더링하고 백그라운드에서 갱신하며, 없으면 `brand.json`이 도착하거나 1초가 지날 때까지 첫 렌더링을 보류합니다. CSS 변수, 아이콘 링크, 테마 색상, 제목을 설정합니다. 관리자 포털은 `branding.get`과 각 저장 결과도 공급하므로 관리자는 변경을 즉시 확인합니다.

## 페이지 렌더러

[페이지 렌더러](./public-pages/)는 렌더링할 때마다 레코드를 읽고(이후 페이지는 300초 동안 캐시됩니다), 제목 접미사, `og:site_name`, JSON-LD 제공자, `og:image`와 `twitter:image`(페이지에 자체 이미지가 없을 때는 공유 이미지), 아이콘 링크, 인라인 `:root` 스타일에 적용합니다. 또한 포털이 이를 바탕으로 시작하도록 페이지 데이터에 브랜드 문서를 포함시킵니다. 읽기에 실패하면 경고를 기록하고 기본 브랜드를 렌더링합니다.

## 색상 팔레트

`@discava/common-branding/colour`의 `brandPalette(hex)`는 덮어쓸 CSS 변수를 반환합니다. `--primary`, `--primary-foreground`, `--ring`, 사이드바용 대응 변수, `--brand-link`입니다. 브랜드 색상에 대해 WCAG 대비율이 더 높은 텍스트 색상을 고르며, 어느 쪽도 4.5:1에 도달하지 못하면 그 색상을 거부합니다. `--brand-link`는 페이지 배경에서 4.5:1에 도달할 때만 브랜드 색상이 됩니다. 같은 함수가 admin-api, 관리자 포털의 미리보기, 포털, 렌더러에서 실행되므로 서로 어긋날 수 없습니다. 의미를 나타내는 색상(파괴적 동작, 차트, 상태)은 건드리지 않습니다.

## 브랜딩 대상이 아닌 것

Cognito의 호스팅 로그인 페이지와 문서 사이트는 자체 디자인을 유지합니다.
