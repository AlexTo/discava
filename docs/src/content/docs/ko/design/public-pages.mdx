강의의 랜딩 페이지(`/learn/<courseId>`)와 강사의 프로필(`/instructors/<handle>`)은 공개되어 있어서 누구나 로그아웃 상태로 열 수 있습니다. 학생 포털은 싱글 페이지 앱이므로, 스크립트를 실행하지 않는 크롤러나 링크 미리보기는 빈 셸만 보게 됩니다. **페이지 렌더러**가 이 주소들에 실제 HTML로 응답해서 이 문제를 해결합니다.

## 페이지 렌더러

렌더러는 `@discava/core-api`의 두 번째 Lambda 핸들러(`src/page-renderer/handler.ts`)입니다. 학생 포털의 CloudFront 배포는 `/learn/*`, `/instructors/*`, `/certificates/*`, `/sitemap.xml`, `/robots.txt`의 오리진으로 이것을 사용합니다. Websites 스택의 `StudentPortal` 구성 요소가 빌드하며, CloudFront만 호출할 수 있는 Function URL을 가집니다. `GET`과 `HEAD`에만 응답합니다.

로컬에서는 `pnpm dev`가 포트 2026에서 시작합니다(`src/local-page-renderer.ts`). 브라우저는 계속 Vite 서버를 사용하고, 크롤러 응답은 이 포트에서 가져옵니다.

| 경로 | 응답 |
|---|---|
| `/learn/<courseId>` | 게시된 강의의 랜딩 페이지, 그 외에는 `404` |
| `/learn/<courseId>/<anything>` | `noindex`가 붙은 일반 `index.html`(로그인한 학습 경로). 아무것도 읽지 않습니다 |
| `/instructors/<handle>` | 게시된 강의를 가르치는 강사의 프로필, 그 외에는 `404` |
| `/certificates/<ID>` | 링크 미리보기를 위한 head(학습자, 강의, 날짜, 플랫폼 이름). 항상 `noindex`이며 알 수 없는 ID는 `404` |
| `/certificates/<ID>/<anything>` | `noindex`가 붙은 일반 `index.html`(LinkedIn 경로) |
| 그 외 모든 경로 | `404` |
| `/sitemap.xml` | 게시된 모든 강의, 공개 프로필, 활성 카테고리를 `lastmod`와 함께 |
| `/robots.txt` | [색인 설정](#색인-설정) 참고 |

페이지에 대해 렌더러는 빌드된 `index.html`을 가져와 다음을 추가합니다.

- head 태그: 제목, 설명, 정규(canonical) 주소, Open Graph와 Twitter 카드 태그, schema.org JSON-LD(`Course`, 또는 `Person`이 있는 `ProfilePage`)
- `#root` 안의 정적 렌더링: 제목, 이미지, 핵심 정보, 학습 성과, 요구 사항, 설명, 커리큘럼 개요, 평점 요약, 리뷰의 첫 페이지, 강사 카드
- 사용한 프로시저 출력을 담은 `<script type="application/json" id="discava-page-data">` 요소
- 플랫폼 브랜드: 아이콘, 색상, 브랜드 문서. 따라서 페이지는 첫 렌더링부터 관리자가 설정한 브랜드를 보여 줍니다(<Link path="design/branding">브랜딩</Link> 참고). 브랜드를 읽을 수 없으면 기본 브랜드로 렌더링됩니다.

부팅 시 포털은 page-data 요소를 읽고 제거한 뒤 그 내용으로 React Query를 채웁니다(`src/lib/page-data.ts`). 그러면 앱의 첫 렌더링이 곧 전체 페이지이므로 정적 마크업을 교체할 때 깜빡임이 없습니다. 모든 텍스트는 HTML 이스케이프되고 JSON은 `<`, `>`, `&`를 이스케이프해 직렬화하므로 강의 제목이 페이지 밖으로 빠져나올 수 없습니다.

**무엇이 공개인지에 대한 단일 진실 공급원.** 렌더러는 `course.publicView`, `review.summary`, `review.list`, `instructorProfile.publicView`, `certificate.verify`를 익명 컨텍스트로 `appRouter.createCaller`를 통해 같은 프로세스 안에서 호출합니다. 따라서 크롤러는 API가 반환하는 것 이상을 볼 수 없습니다. 초안 강의, 보관된 강의, 알 수 없는 ID는 바이트 단위로 동일한 `404` 페이지를 받습니다. 이는 해당 강의에 등록한 학생을 포함해 모두에게 적용됩니다. 내 학습을 통한 그들의 접근은 달라지지 않습니다.

**정규 주소**는 뷰어의 호스트를 사용하며, CloudFront Function이 이를 `x-discava-host`로 복사합니다. 호스트는 해당 스테이지의 학생 포털 도메인 중 하나(설정된 것이 없으면 `*.cloudfront.net` 호스트)일 때만 사용됩니다. 다른 호스트는 처음 설정된 도메인으로 대체되므로, 도메인을 배포에 연결해도 정규 주소를 오염시킬 수 없습니다.

**의존성이 실패하면**(테이블, 설정 파라미터, `index.html` 읽기) 응답은 `Cache-Control: no-store`, `X-Robots-Tag: noindex`, `Retry-After: 5`가 붙은 일반 텍스트 `503`(`Service temporarily unavailable`)입니다. 캐시되지 않으며 `404`로 바뀌는 일도 없습니다. HTML이 없으므로 장애 중에 랜딩 페이지나 프로필을 로드한 방문자는 앱이 아니라 그 텍스트를 보게 됩니다. 앱 내 이동은 렌더러에 도달하지 않으므로 계속 동작합니다.

## 캐싱과 최신성

CloudFront는 각 응답을 캐시합니다.

| 응답 | `Cache-Control` |
|---|---|
| 페이지 또는 셸 | `max-age=0, s-maxage=300`: CloudFront는 5분간 보관하고 브라우저는 항상 재검증합니다 |
| 찾을 수 없음 | `max-age=0, s-maxage=60` |
| `sitemap.xml`, `robots.txt` | `max-age=300, s-maxage=300` |
| `503` | `no-store` |

캐시 키는 경로뿐입니다. 쿼리 문자열, 쿠키, `Authorization` 헤더는 전달되지 않으므로 응답이 요청한 사람에 따라 달라지지 않습니다.

그러면 무효화 없이도 오래된 정도가 **5분**으로 제한됩니다. 강의나 프로필의 변경은 5분 안에 크롤러와 링크 미리보기에 반영되고, 보관된 강의나 공개 상태가 끝난 프로필도 같은 시간 안에 `404`로 응답하기 시작합니다. 브라우저의 방문자는 앱이 API를 읽기 때문에 다음 로드에서 변경을 봅니다.

렌더러는 캐시 미스마다 조건부 `GetObject`(`If-None-Match`, 보통 `304`)로 포털의 `index.html`을 확인하며, 이전 사본으로 대체하지 않습니다. 포털을 배포하면 해시가 붙은 오래된 에셋을 정리한 뒤 전체 배포를 무효화하므로, 캐시된 어떤 페이지도 더 이상 존재하지 않는 번들을 가리키지 않습니다.

## 싱글 페이지 앱 리라이트

기본 동작의 CloudFront Function(`spa-rewrite.js`, 공유 `StaticWebsite` 구성 요소 안)은 마지막 세그먼트에 파일 확장자가 없는 모든 경로를 `/index.html`로 다시 씁니다. 없는 에셋은 S3의 오류를 받고, 렌더러의 `404`는 뷰어에게 전달됩니다. 세 포털 모두 공유 구성 요소를 통해 이를 적용받습니다.

배포에는 `404`나 `403`을 `200`의 `/index.html`로 바꾸는 오류 응답이 없습니다. 그런 설정은 배포의 모든 오리진에 적용되므로 렌더러의 `404`를 검색 엔진이 소프트 404로 취급하는 성공 페이지로 바꿔 버릴 것입니다.

## 색인 설정

`studentPortal.allowSearchEngineIndexing`은 스테이지별 설정이며 기본값은 `false`이고 `discava-production`에서만 `true`입니다. (여기서 "indexing"은 이미 OpenSearch 색인을 뜻하므로 단독으로 부르지 않습니다.)

| | 설정 끔 (다른 모든 스테이지, 로컬 개발) | 설정 켬 (프로덕션) |
|---|---|---|
| 페이지 | 모든 렌더러 응답에 `<meta name="robots" content="noindex">`와 `X-Robots-Tag: noindex` | 찾을 수 없음 응답과 랜딩이 아닌 `/learn/*` 셸에만 `noindex`. `/certificates/*`는 항상 `noindex` |
| S3의 파일 | 응답 헤더 정책이 `X-Robots-Tag: noindex`를 추가함 | 표시 없음 |
| `/robots.txt` | `Disallow: /` | `/learn/*/`, `/my-learning`, `/signin`, `/search`를 막고 나머지는 허용하며 사이트맵을 나열함 |

크롤러용 콘텐츠와 소셜 카드는 모든 스테이지에서 제공되므로 프로덕션 전에 테스트할 수 있습니다.

사이트맵은 요청 시 키 기반 읽기와 선언된 인덱스로 만들며, 스캔은 하지 않습니다(`helpers/sitemap.ts`). 하나의 파일이며 사이트맵 프로토콜은 이를 50,000개 URL로 제한합니다. 이를 넘으면 사이트맵 인덱스가 후속 작업입니다.

## 미리보기 동영상의 노출 규칙

강의에는 강사가 별도 파일로 업로드한 5분 이하의 미리보기 동영상을 하나 둘 수 있습니다. 레슨 동영상처럼 트랜스코딩과 자막 처리가 되며, 교체하면 새 버전이 준비될 때까지 이전 버전이 계속 재생됩니다. 이 레코드인 `coursePreview`는 `course`와 분리되어 있으므로, 트랜스코딩이나 자막 상태가 바뀌어도 `course.updatedAt`이 움직이거나 검색 재색인이 트리거되지 않습니다.

로그인 여부와 관계없이 누구나 재생할 수 있지만 다음 규칙 아래에서만 가능합니다.

- `course.previewVideoUrl`은 공개이며, 강의가 **게시**되어 있고 미리보기에 **재생 가능한 버전**이 있을 때만 응답합니다. 그렇지 않으면 존재하지 않는 강의처럼 동작합니다.
- 이것이 설정하는 서명된 쿠키는 **그 버전의 폴더만**(렌더링 버전과 자막 트랙) 포함하며, 수명은 등록한 학생의 것과 같습니다. 등록 없이는 강의의 레슨 동영상, 파일, 다른 콘텐츠에 접근할 수 없습니다.
- 보관된 강의는 즉시 미리보기 제공을 멈추며, 복원되면 다시 재생합니다. 교체되거나 제거된 버전은 새 주소를 발급하지 않으며, 파일은 레슨 동영상처럼 나중에 삭제됩니다.
- 이 프로시저는 `PUBLIC_OPERATIONS`에 있으므로 공개 요청 한도가 적용되고, 활성화된 경우 스테이지의 웹 방화벽도 적용됩니다.

## 무료 미리보기 레슨

강사는 일반 레슨을 무료 미리보기로 표시할 수 있습니다. 그러면 로그인 여부나 등록 여부와 관계없이 누구나 `/learn/<courseId>/preview/<lessonId>`에서 열 수 있습니다. 이는 "결제하지 않은 사용자는 유료 콘텐츠를 얻을 수 없다"는 규칙의 의도적인 유일한 예외입니다.

**표시.** 레슨에는 선택 사항인 `freePreview` 속성이 있으며, `true`로만 저장되고 표시를 해제하면 제거됩니다(instructor-api의 `lesson.setFreePreview`). `lesson` 종류의 레슨만 이를 가질 수 있습니다. 과제 레슨은 표시할 수 없으며, `free-preview-on-ordinary-lesson` 테이블 불변 조건이 표시된 과제 레슨을 잡아냅니다.

`@discava/core-table`의 `isOpenFreePreview`가 성립하면 레슨은 **열린** 미리보기입니다. 이 함수가 "열림"의 유일한 정의입니다.

- 강의가 게시되어 있습니다.
- 모듈과 레슨이 표시됩니다(보이며 보관되지 않음).
- 레슨이 일반 레슨이며 표시되어 있습니다.

**자체 공개 작업 세 가지.** `freePreview.lesson`, `freePreview.videoUrl`, `freePreview.fileUrl`은 core-api의 공개 쿼리이며 `PUBLIC_OPERATIONS`에 나열되어 있습니다. 호출자를 읽지 않으므로 로그아웃한 방문자, 등록하지 않은 사용자, 등록한 학생이 같은 응답을 받습니다.

등록 사용자용 프로시저(`course.view`, `contentItem.videoUrl`, `contentItem.fileUrl`, `quiz.view`, 진행률, 완료, 과제, 토론 프로시저 및 나머지)는 건드리지 않으며, 표시된 레슨도 다른 레슨과 마찬가지로 여전히 등록이 필요합니다. 공개 작업에는 클레임이 없으므로 하나의 작업이 방문자와 등록한 학생을 모두 처리할 수 없습니다.

**응답에 담기는 것.** 각 항목은 필드별로 만들어지므로 이름을 붙이지 않은 것은 밖으로 나가지 않습니다.

| 항목 | 방문자가 받는 것 |
|---|---|
| 동영상 | 제목, 설명, 길이, 지금 재생할 수 있는지 여부 |
| 텍스트 | 본문 |
| 파일 | 이름, 크기, 유형 |
| 퀴즈 | 제목과 문항 수만, 잠긴 카드로 표시. 문제, 정답, 설정은 없음 |
| 과제 | 제외됨 |

스토리지 키, 상태, 작업 속성은 반환되지 않습니다. 열린 미리보기가 아닌 레슨이나 그 아래에 표시되지 않는 항목을 지정한 호출자는 이유와 관계없이 같은 `NOT_FOUND`를 받으며, 아무것도 서명되지 않습니다.

**서명.**

- 동영상의 쿠키는 그 버전의 폴더만 포함하고, 그 `Path`로 설정되며, 등록한 학생이 받는 4시간과 달리 **한 시간**(`FREE_PREVIEW_COOKIE_LIFETIME_SECONDS`) 지속됩니다.
- 페이지는 방문자가 재생을 누를 때 주소를 요청하고, 동영상이 재생되는 동안 30분마다 다시 요청하여 쿠키를 갱신합니다.
- 파일 링크는 하나의 객체에 대해 5분간 유효합니다. 텍스트는 서명이 필요하지 않습니다.
- 한 시간은 `RETIRED_VERSION_DELAY_MINUTES`가 이미 포괄하는 쿠키 수명을 넘지 않으므로, 교체된 버전의 파일은 모든 미리보기 쿠키보다 오래 남습니다. 단위 테스트가 이를 고정합니다.

**표시를 해제하면 일어나는 일.** 작업은 매 요청마다 레슨을 읽고 아무것도 캐시하지 않습니다. 쓰기 이후(또는 레슨, 모듈, 강의가 숨겨지거나 보관된 이후) 첫 요청부터 세 작업 모두 `NOT_FOUND`로 응답하며, 새 접근은 없습니다. 공유된 미리보기 주소는 이후 "This preview is no longer available"을 표시합니다.

**표시를 해제해도 일어나지 않는 일.** 이미 제공된 것을 회수하지는 않습니다.

- 동영상 쿠키는 만료될 때까지, 발급 후 최대 한 시간 동안 계속 동작하며 갱신되지 않습니다.
- 파일 링크는 최대 5분간 동작합니다.
- 화면의 텍스트, 다운로드한 파일, 녹화본은 회수할 수 없습니다.

페이지 렌더러가 캐시하므로 랜딩 페이지는 최대 5분간 "Free preview" 라벨을 표시할 수 있습니다.

**아무것도 기록되지 않습니다.** 미리보기는 쓰기를 하지 않으며 호출자에 대해 아무것도 읽지 않습니다. 완료, 진행률, 저장된 동영상 위치, 퀴즈 응시, 학생 활동 수, 토론이 없습니다. 동영상은 방문할 때마다 처음부터 시작합니다. 이는 모든 학생 레코드가 수강 등록에 연결되도록 유지하며, 이는 모든 e2e 테스트 후에 `student-records-enrolled`가 확인합니다.

**유료 콘텐츠 규칙.** 이 규칙의 데이터 형태인 `paid-course-enrolment-paid`는 바뀌지 않습니다. 미리보기는 수강 등록을 만들지 않습니다. API 형태는 `paid-access.test.ts`에서 테스트하며, 등록하지 않은 로그인 사용자로 유료 강의를 대상으로 모든 콘텐츠 프로시저를 실행하고, 열린 미리보기 레슨을 대상으로도 다시 실행하여 같은 `FORBIDDEN` 거부를 확인합니다. 열린 미리보기 레슨은 명시된 유일한 예외이며, 이에 대한 테스트는 `procedures/free-preview.test.ts`에 있습니다(대상이 열린 미리보기가 아닌 모든 경우의 거부 매트릭스).

**크롤러.** 렌더러는 랜딩 페이지의 개요에서 각 열린 미리보기 레슨을 표시합니다. 제목이 미리보기 주소로 연결되고 그 뒤에 "Free preview"가 붙습니다. 레슨의 콘텐츠는 크롤러용으로 렌더링되지 않습니다. 미리보기 주소 자체는 `noindex`가 붙은 일반 페이지로 제공되고, `robots.txt`(`/learn/*/`)가 막으며, 사이트맵에 없습니다. 텍스트를 렌더링하면 표시되지 않은 레슨이 검색 엔진의 캐시에서 읽힐 수 있게 됩니다.

**운영자 참고: 대역폭.** 플랫폼이 미리보기 동영상 전송 비용을 부담하며, 하나의 서명으로 한 시간 동안 스트리밍할 수 있습니다. 공개 스로틀은 서명이 발급되는 빈도를 제한할 뿐 하나의 서명이 스트리밍하는 바이트 수는 제한하지 않으며, 누구나 홍보 동영상처럼 미리보기 동영상을 스트리밍할 수 있습니다. 미디어 배포(미디어 버킷 앞의 배포)의 CloudFront 데이터 전송 지표를 CloudFront 콘솔이나 CloudWatch에서 확인하고, core API 게이트웨이 스테이지의 `freePreview.*` 메서드에 대한 429 횟수를 확인하세요. 방문자별 속도 규칙이나 강의당 표시 가능한 레슨 수의 상한은 후속 작업으로 가능합니다.

## 프로필과 핸들

강사의 프로필은 첫 강의와 함께 만들어지므로 강사 카드는 항상 연결할 곳이 있습니다. `course.create`는 강의 자체의 트랜잭션 직전에 `ensureInstructorProfile`(`@discava/core-table`)을 호출합니다. 이는 멱등적이며, 강의가 없는 프로필도 어떤 불변 조건도 깨지 않습니다.

- URL은 계정 ID가 아니라 **핸들**을 사용합니다. 소문자, 숫자, 단일 하이픈으로 이루어진 3~30자입니다. 카테고리 이름처럼 클레임 레코드(`profileHandleClaim`)를 통해 강사 전체에서 고유합니다.
- 프로필은 소유자가 게시된 강의를 하나 이상 가르칠 때, 그리고 그때만 공개이며, 정확히 그 강의들만 나열합니다. 거부 옵션은 없습니다.
- 공개 출력에는 이메일 주소나 계정 식별자가 없습니다.
