강좌는 **카테고리**(강좌당 하나, 관리자가 관리하는 분류 체계에서 선택)로 정리하고 다른 선택 필드 네 개로 설명할 수 있습니다. 학생은 이 모든 항목으로 카탈로그를 필터링합니다.

## 강좌 카탈로그 필드

| 필드 | 규칙 |
|---|---|
| `categoryId` | 설정하거나 변경할 때 존재하는 **활성** 카테고리여야 함 |
| `tags` | 최대 8개, 각각 1~30자. 공백을 제거하고 소문자로 저장하며 중복은 제거 |
| `level` | `beginner`, `intermediate`, `advanced` |
| `language` | 고정 목록의 코드 |
| `durationHours` | 1~500의 정수 |

다섯 필드 모두 선택 사항입니다. 강사는 강사 포털에서 instructor-api의 `course.updateCatalogue`로 값을 설정하고 `category.listActive`에서 카테고리를 고릅니다. core-table의 `helpers/course-catalogue.ts`에 있는 `courseCatalogueWrites`만이 이 다섯 필드의 작성자이므로, 모든 작성자가 같은 방식으로 검증합니다.

## 카테고리 분류 체계

카테고리는 다음을 가집니다.

- `name`: 1~60자, 대소문자와 공백을 무시하고 고유함
- `slug`: URL에 안전하며 생성 시 이름에서 만들어지고 이후 바뀌지 않음. 슬러그가 이미 있으면 숫자를 붙임(`design`, `design-2`)
- `status`: `active` 또는 `archived`

분류 체계 전체가 core-table의 파티션 하나에 있으므로 목록 조회는 쿼리 한 번입니다. 카테고리는 삭제되지 않습니다. 보관하면 새 과제용 선택 목록에서는 숨겨지지만, 이미 그 카테고리를 쓰는 강좌는 그대로 유지합니다.

고유성은 카테고리와 같은 트랜잭션에서 기록되는 `categoryClaim` 레코드로 강제됩니다. 슬러그용과 정규화된 이름용, 두 개입니다. 이름을 바꾸면 이름 클레임만 옮겨지고 슬러그는 그대로이므로 카테고리 랜딩 페이지 URL은 바뀌지 않습니다. core-table의 `helpers/category.ts`가 두 레코드의 유일한 작성자입니다.

불변 조건 검사 `course-category-exists`와 `category-claims-consistent`는 강좌가 존재하는 카테고리만 가리키고, 모든 카테고리가 정확히 두 개의 클레임을 갖도록 보장합니다.

## 관리자 포털과 `admin-api`

관리자(`admin` Cognito 그룹)는 관리자 포털에서 카테고리를 관리하며, 포털은 **`admin-api`**를 호출합니다. 이는 instructor-api와 같은 방식으로 만든 별도의 tRPC API로 자체 Lambda와 API Gateway를 가지므로, 관리자만 해당 프로시저에 접근할 수 있습니다. 프로시저는 `category.list`, `create`, `rename`, `archive`입니다.

학생과 방문자는 core-api의 공개 `category.list`와 `category.bySlug`로 카테고리를 읽으며, 카테고리 랜딩 페이지가 이를 사용합니다.

새 스테이지에는 카테고리가 없습니다. `pnpm nx run @discava/tooling-deploy:seed-categories`는 기본 세트를 기록하며 이미 있는 항목은 건너뜁니다.

## 검색 패싯

카테고리, 태그, 수준, 언어, 기간은 `courses` 검색 인덱스에 색인되며, 검색은 각각에 대한 패싯 개수를 반환합니다. 패싯 쿼리와 배포 후 실행해야 하는 일회성 재색인은 <Link path="design/search">검색</Link>을 참고하세요.
