**Spec:** [`specs/20261120-154551-first-lesson-start/`](https://github.com/AlexTo/discava/tree/main/specs/20261120-154551-first-lesson-start/) (활성화, 그리고 첫 레슨 안내의 응답과 닫기)

강사 포털의 대시보드는 강좌마다 요약 카드 하나를 보여 주며, 각 카드는 해당 강좌의 분석 페이지로 연결됩니다. 두 화면 모두 core 테이블의 스트림에서 최신 상태로 유지되는 저장된 수치를 읽습니다. 요청 시점에 레코드에서 집계하는 것은 없으므로, 수강생이 아무리 많아도 페이지가 빠르게 로드됩니다.

포털은 instructor-api의 `analytics.courseSummaries`(카드), `analytics.course`, `analytics.quiz`, `analytics.videoQuestions`로 이를 읽습니다.

## 정의

| 수치 | 정의 |
|---|---|
| **Enrolments** [수강 등록] | 강좌가 지금까지 받은 모든 수강 등록이며 중도 포기한 학생도 포함합니다. 이력 차트는 각 등록을 학생이 등록한 UTC 날짜에 집계합니다 |
| **Dropped** [중도 포기] | 상태가 dropped인 수강 등록. 수강 등록 이력에는 남지만 아래의 다른 모든 수치에서는 제외됩니다 |
| **Active learner** [활성 학습자] | 항목을 완료했거나(과제 제출 포함), 퀴즈 응시를 제출했거나, 동영상 질문에 답한 수강 중인 학생. 로그인이나 페이지 열기는 기록되지 않으므로 포함되지 않습니다 |
| **Active this week** [이번 주 활성] | 현재 달력상 주(UTC 기준 월요일부터 일요일)의 고유한 활성 학습자 수. 분석 페이지는 최근 30일 또는 90일의 UTC 일별 고유 활성 학습자 수도 보여 줍니다 |
| **Completion rate** [완료율] | 완료된 수강 등록을 중도 포기하지 않은 모든 수강 등록으로 나눈 값. 해당하는 수강 등록이 없는 강좌는 0%가 아니라 "No data"로 표시됩니다 |
| **Activated** [활성화됨] | 강좌에서 첫 활동을 한 수강 등록. 수강 등록에 마지막 활동 시각이 있다는 뜻이며, 이 시각은 첫 완료 항목, 퀴즈 응시, 과제 제출, 동영상 질문 응답 중 먼저 일어난 것으로 설정됩니다. 종료된 수강 등록을 포함한 모든 수강 등록이 집계됩니다. 수강 등록의 마지막 활동 시각에서 집계하므로 새 표식을 따로 보관하지 않으며, "현재까지" 기준입니다. 아직 시작하지 않은 학습자도 나중에 활성화될 수 있습니다. 이력 차트는 이를 학생이 등록한 UTC 날짜에 귀속시킵니다 |
| **Activation rate** [활성화율] | 활성화된 수강 등록을 모든 수강 등록으로 나눈 값이며, 분자와 분모 모두 종료된 수강 등록을 포함합니다. 전체 기간, 그리고 최근 30일 또는 90일에 등록한 학습자 기준으로 표시됩니다. 수강 등록이 없는 강좌는 0%가 아니라 "No data"로 표시됩니다 |
| **Prompt answers and dismissals** [안내 응답과 닫기] | 첫 레슨 안내에 응답한 학습자 수와 **Not now**를 누른 학습자 수. 학습자는 강좌당 한 번만 집계됩니다. 안내가 몇 번 표시되었는지는 기록하지 않으므로 비율은 없습니다 |
| **Drop-off** [이탈] | 현재 학생에게 표시되는 각 레슨에 대해 강좌 순서대로: 시작한 학습자 수, 완료한 학습자 수, 시작한 학습자 중 완료한 비율. 숨겨지거나 보관된 레슨, 숨겨지거나 보관된 모듈의 레슨은 제외됩니다 |
| **Score bands** [점수 구간] | 퀴즈별 각 학생의 최고 점수를 10점 단위 구간(0-9, 10-19, ... 90-100)으로 나눈 것. 응시 횟수와 관계없이 학생은 한 번만 집계됩니다 |
| **Most-missed questions** [가장 많이 틀린 문제] | 모든 응시에 걸친 오답률 순위. 문제가 순위에 오르려면 응시가 최소 5회 필요하므로, 한 번의 나쁜 응시가 문제를 1위로 올릴 수 없습니다 |
| **Video question results** [동영상 질문 결과] | 질문이 있고 학생에게 표시되는 각 동영상에 대해, 그리고 현재 질문별로: 질문 시점(또는 "End of video"), 질문 프롬프트의 시작 부분, 응답한 학습자 수, 오답 수, 오답률. 퀴즈 문제와 같은 방식으로 순위가 매겨지며 최소 응답 5개 조건이 같습니다. 각 학습자의 첫 번째 기록된 응답만 집계되며, **Try again**과 건너뛰기는 기록되지 않습니다. 삭제된 질문은 나열되지 않습니다. 결과에는 학습자 식별자가 없습니다 |
| **Modules without questions** [질문이 없는 모듈] | 레슨 이탈 보기에는 표시되는 동영상이 있지만 표시되는 퀴즈도 없고 질문이 있는 표시되는 동영상도 없는 학생에게 표시되는 모듈의 이름도 나오며, 강사에게 질문 추가를 제안합니다. 현재 커리큘럼에서 읽으므로 집계값이 아니며 어긋날 수 없습니다 |

## 최신성

수치는 강좌 진행률처럼 레코드보다 몇 초 늦습니다. 변경(수강 등록, 완료, 퀴즈 응시)은 보통 30초 안에 다음 로드에서 나타납니다. 카드와 분석 페이지 모두 수치가 마지막으로 갱신된 시각을 보여 줍니다.

## 수치가 유지되는 방식

`analytics-update` 핸들러는 <Link path="design/stream-event-router">스트림 이벤트 라우터</Link> 기능입니다. 이 핸들러는 core 테이블의 레코드 다섯 개, 즉 `courseStats`, `periodStats`, `lessonStats`, `quizScoreStats`, `quizQuestionStats`에 카운터를 유지합니다.

- **각 변경은 한 번만 집계됩니다.** 변경의 카운트는 스트림 레코드 이름을 딴 `analyticsMarker`와 같은 트랜잭션에서 기록됩니다. 다시 전달된 레코드는 자신의 표식을 발견하고 아무것도 집계하지 않습니다.
- **각 학습자는 하루와 한 주에 한 번만 집계됩니다.** 학습자와 기간별 두 번째 표식 덕분에 "활성"은 고유한 학습자의 수가 됩니다.
- **순서는 중요하지 않습니다.** 카운터는 더하기만 하며, 레슨의 이탈 수치는 도착한 변경이 아니라 학생의 현재 레코드를 기준으로 확정됩니다.

수치가 레코드와 어긋나면 `analytics-matches-records` 불변 조건이 이를 찾아내며, `pnpm nx run @discava/tooling-deploy:rebuild-analytics -- <courseId>`는 레코드에서 강좌의 수치를 다시 계산합니다.
