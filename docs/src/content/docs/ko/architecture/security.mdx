## 누가 무엇을 할 수 있나

접근은 계층별로 결정되며, 각 계층은 앞선 계층이 실패할 수 있다고 가정합니다.

| 계층 | 강제하는 것 |
| --- | --- |
| **Cognito 그룹** | 사용자의 역할: `student`, `instructor`, `admin` |
| **분리된 API** | 강사와 관리자 프로시저는 별도 배포입니다. 학생의 토큰은 어떤 프로시저가 실행되기 전에 instructor-api가 거부합니다 |
| **프로시저 규칙** | 구체적인 규칙: 이 강사가 이 강좌를 소유한다, 이 학생이 이 강좌에 수강 등록되어 있다 |
| **서명된 미디어** | 동영상이나 파일은 그것을 위해 서명된 요청에만 제공됩니다. 서명은 수강 등록 같은 접근 확인 후에 발급됩니다 |

초안이나 보관된 강좌는 볼 권한이 없는 사람에게 "찾을 수 없음"으로 응답하므로, 존재 자체가 드러나지 않습니다.

## 스테이지별 보호 기능

모든 보호 기능은 **기본적으로 켜져 있습니다**. 스테이지 구성에서는 끌 수만 있으며, `discava-development`는 비용을 낮추기 위해 이를 끕니다.

| 보호 기능 | 하는 일 | 프로덕션 | 개발 |
| --- | --- | --- | --- |
| **WAF** | 포털, API, 미디어, 사용자 풀의 웹 애플리케이션 방화벽 | 켜짐 | 꺼짐 |
| **KMS 암호화** | 테이블, 버킷, 큐, 로그, 검색에 대한 고객 관리형 키와 키 교체 | 켜짐 | 꺼짐 (AWS 관리형 암호화) |
| **MFA** | 로그인 시 두 번째 인증 요소 | 켜짐 | 꺼짐 |
| **삭제 방지** | 사용자 풀과 테이블 삭제를 거부 | 켜짐 | 꺼짐 |
| **삭제 시 보존** | 스택을 제거해도 데이터를 유지 | 켜짐 | 꺼짐 |
| **자체 가입** | 누구나 계정을 만들 수 있게 허용 | 켜짐 | 꺼짐 |
| **트레이싱** | X-Ray 요청 추적 | 켜짐 | 꺼짐 |

데이터는 항상 저장 시와 전송 시 암호화됩니다. KMS 설정은 그 키를 직접 제어하고 감사할 수 있는지를 결정합니다.

WAF가 꺼진 개발 스테이지에서는, 스테이지 구성의 요청 제한, 함수 동시성, 테이블 처리량 상한이 요청 폭주로 인한 비용의 한도가 됩니다. 자체 가입이 꺼져 있으면 외부인이 계정을 얻어 로그인 사용자용 프로시저에 접근할 수 없습니다.

## 시스템 내부의 최소 권한

- 각 Lambda 함수는 자기 작업에 필요한 권한만 가진 고유한 역할을 가집니다.
- 민감한 기능은 전용 함수로 분리합니다. 강의 미디어 요청에 서명하는 키는 core-api의 함수 하나와 instructor-api의 함수 하나만 읽을 수 있고, 나머지 모든 프로시저를 처리하는 함수는 읽을 수 없습니다.
- Stripe 키와 웹훅 서명 시크릿은 Secrets Manager에 있습니다. admin-api의 함수 하나만 이를 쓸 수 있습니다. 결제, 웹훅, 정산 계정, 정산 실행 함수는 필요한 것만 읽으며, 응답, 로그, 감사 기록 어디에도 둘 중 어느 것도 담기지 않습니다.
- Stripe 웹훅은 저장된 서명 시크릿으로 서명이 검증되는 메시지만 받아들입니다. 결제를 브라우저의 말만 믿고 처리하지 않습니다.
- 공개된 S3 버킷은 없습니다. 포털과 미디어는 CloudFront 배포를 통해서만 접근할 수 있습니다.
- 페이지 렌더러는 테이블에 대한 읽기 전용 권한으로 공개 페이지를 제공하며, 학생 포털의 CloudFront 배포만 이를 호출할 수 있습니다.
- 각 API는 자신을 호출하는 포털의 교차 출처 요청에만 응답합니다. core-api는 세 포털 모두, instructor-api는 강사 포털, admin-api는 관리자 포털입니다. 로컬 개발 주소도 허용됩니다.
- 검색 인덱스는 색인 함수만 씁니다. API는 읽기만 할 수 있습니다.
- 함수는 배포 시점의 환경 변수에서 리소스 이름을 받으며, 자격 증명은 코드나 환경 파일에 나타나지 않습니다.

## 코드를 배포하기 전의 검사

| 검사 | 위치 | 잡아내는 것 |
| --- | --- | --- |
| **Checkov** | 모든 빌드 | 생성된 템플릿의 안전하지 않은 인프라 설정 |
| **Trivy** | CI와 각 배포 전 | 의존성의 알려진 취약점과 커밋된 시크릿 |
| **git-secrets** | 각 커밋 전 | 커밋하려는 자격 증명 |
| **테이블 불변식** | 엔드투엔드 테스트 | 여러 레코드에 걸친 규칙을 깨뜨린 상태로 남은 데이터 |

## 배포를 범위 안에 두기

배포 파이프라인 자체가 공격 표면이므로 제약을 둡니다.

- **저장된 AWS 자격 증명 없음.** GitHub Actions는 한 번의 실행을 위해 발급된 토큰으로 로그인합니다.
- **배포 역할은 한 저장소의 한 환경만 신뢰합니다.** 그 환경에 필수 검토자를 지정하면 배포를 통제할 수 있습니다.
- **배포 역할은 리소스를 만들 수 없습니다.** 자기 스테이지 이름이 붙은 스택을 배포하도록 CloudFormation에 요청할 수만 있습니다.
- **실행 역할은** 스테이지의 리소스로 이름 기준 범위가 제한됩니다.
- **권한 경계**가 스테이지가 만드는 모든 역할을 제한하므로, 배포된 변경이 경계가 허용하는 것보다 많은 권한을 스스로 부여할 수 없습니다.

로그인 방식과 두 역할은 <Link path="deploy/ci-cd">CI/CD 레퍼런스</Link>에서 설명합니다.
