## 구성이 있는 곳

모든 스테이지는 한 파일 `packages/common/infra-config/src/stages.config.ts`에 정의됩니다. 스테이지는 `infra` 아래에 **구성 요소**별 설정을 나열합니다.

| 구성 요소 | 설명 |
| --- | --- |
| `identity` | Cognito 사용자 풀 |
| `coreApi`, `instructorApi`, `adminApi` | 세 개의 API |
| `payments` | Stripe 웹훅 API |
| `coreTable` | DynamoDB 테이블 |
| `streamRouter` | 테이블 변경을 핸들러로 전달하는 큐 |
| `studentPortal`, `instructorPortal`, `adminPortal` | 세 개의 웹사이트 |
| `lessonMedia`, `publicMedia` | 동영상과 이미지 버킷, 그리고 그 CloudFront 배포 |
| `search` | OpenSearch Serverless 컬렉션 |
| `notifications` | 이메일 발신자 |

**모든 보안 설정은 기본적으로 켜져 있습니다.** 스테이지는 완화하거나 크기를 정하는 것만 나열합니다. `discava-development`는 비용을 낮추려고 대부분의 보호 기능을 끄고, `discava-production`은 강화된 값을 명시적으로 적어 둡니다.

공통 설정:

| 설정 | 의미 |
| --- | --- |
| `enableWaf` | 구성 요소 앞에 WAF 웹 ACL을 둡니다 |
| `enableKmsEncryption`, `enableKeyRotation` | 고객 관리형 KMS 키로 암호화하고, 그 키를 교체합니다 |
| `retainOnDelete`, `enableDeletionProtection` | 스택이 삭제되어도 데이터를 유지하고, 실수로 인한 삭제를 거부합니다 |
| `throttleRateLimit`, `throttleBurstLimit` | API Gateway의 메서드별 요청 제한 |
| `reservedConcurrency` | API 함수가 동시에 처리하는 최대 요청 수 |
| `maxReadRequestUnits`, `maxWriteRequestUnits` | 테이블의 처리량 상한 |
| `min…CapacityInOcu`, `max…CapacityInOcu` | 검색 용량. 최소가 0이면 유휴 시 0으로 줄어듭니다 |
| `timeoutSeconds`, `logLevel`, `enableTracing` | API의 요청 타임아웃, 최저 로그 수준(`DEBUG`, `INFO`, `WARN`, `ERROR`), X-Ray 트레이싱 |
| `publicThrottle…`, `publicSuggestThrottle…` | 로그인이 필요 없는 호출과 검색 추천에 대한 core API의 별도 제한 |
| `enableSelfSignUp`, `enableMfa` | 누구나 계정을 만들 수 있는지, MFA가 필수인지 |
| `studentPortal.allowSearchEngineIndexing` | 검색 엔진이 공개 페이지를 색인하도록 허용합니다. 설정하지 않으면 꺼짐이며, `discava-production`은 켭니다 |
| `studentPortal.linkedInOrganizationId` | 학생이 LinkedIn에 추가하는 수료증에 표시되는, 내 LinkedIn 조직 페이지 ID |

`packages/common/infra-config/src/stages.types.ts`에 모든 설정과 기본값이 문서화되어 있습니다.

WAF가 꺼져 있으면, 요청 폭주로 인한 비용은 스로틀, 동시성, 처리량 제한이 한도가 됩니다. 실제 사용량이 늘면 이 값을 올리세요.

## 커밋하지 않고 재정의하기

도메인이나 인증서 ARN처럼 내 계정에 고유한 값은 공개 포크에 커밋하면 안 됩니다. 대신 모든 구성 요소 설정을 다음 이름의 변수로 줄 수 있습니다.

```
<STAGE>_INFRA_<COMPONENT>_<FIELD>
```

대문자 스네이크 케이스입니다. 예를 들어 `discava-development`의 `coreApi.throttleRateLimit`은 `DISCAVA_DEVELOPMENT_INFRA_CORE_API_THROTTLE_RATE_LIMIT`입니다.

**스테이지의 GitHub 환경 변수**로 설정하세요. Deploy 워크플로는 스테이지 접두사로 시작하는 모든 변수를 전달합니다.

```sh
gh variable set DISCAVA_DEVELOPMENT_INFRA_CORE_API_THROTTLE_RATE_LIMIT \
  --env discava-development --body 5
```

값은 한 줄의 평문입니다. `true` 또는 `false`, 정수, 또는 `…_DOMAIN_NAMES` 설정용 쉼표로 구분한 목록입니다. 종류가 잘못된 값은 배포를 실패시킵니다.

구성 요소 밖의 항목:

- `<STAGE>_REGION`과 `<STAGE>_ACCOUNT`는 스테이지의 `region`과 `account`를 재정의합니다
- `<STAGE>_CAPTION_TRANSLATION_ENABLED`와 `<STAGE>_CAPTION_TRANSLATION_MAX_LANGUAGES_PER_COURSE`는 [자막 번역](#자막-번역)을 재정의합니다
- `credentials`와 `payouts`는 재정의할 수 없습니다. `stages.config.ts`에서 바꾸세요

## 사용자 지정 도메인

각 API, 포털, 미디어 배포는 자체 도메인을 가질 수 있습니다. 각각에 필요한 것은 다음과 같습니다.

- 내가 제어하는 **도메인 이름**
- 올바른 리전에서 그 도메인을 포함하는, **발급된 ACM 인증서**
- 그 도메인을 가리키는 **DNS 레코드**. 배포 후에 만듭니다

| 구성 요소 | 도메인용 변수 | 인증서 리전 |
| --- | --- | --- |
| Core API | `…_INFRA_CORE_API_DOMAIN_NAME` | 스테이지의 리전 |
| Instructor API | `…_INFRA_INSTRUCTOR_API_DOMAIN_NAME` | 스테이지의 리전 |
| Admin API | `…_INFRA_ADMIN_API_DOMAIN_NAME` | 스테이지의 리전 |
| Payments (Stripe 웹훅 API) | `…_INFRA_PAYMENTS_DOMAIN_NAME` | 스테이지의 리전 |
| 학생 포털 | `…_INFRA_STUDENT_PORTAL_DOMAIN_NAMES` | `us-east-1` |
| 강사 포털 | `…_INFRA_INSTRUCTOR_PORTAL_DOMAIN_NAMES` | `us-east-1` |
| 관리자 포털 | `…_INFRA_ADMIN_PORTAL_DOMAIN_NAMES` | `us-east-1` |
| 강의 미디어 | `…_INFRA_LESSON_MEDIA_DOMAIN_NAMES` | `us-east-1` |
| 공개 미디어 | `…_INFRA_PUBLIC_MEDIA_DOMAIN_NAMES` | `us-east-1` |

각각 짝이 되는 `…_CERTIFICATE_ARN`도 받습니다. 도메인은 인증서도 설정되어 있을 때만 적용됩니다. 포털과 미디어는 쉼표로 구분한 여러 도메인을 받고, API는 하나만 받습니다.

**가장 쉬운 설정 방법은 설정 스크립트를 다시 실행하는 것입니다.** 루트 도메인을 알려 주면 각 구성 요소를 그 도메인의 정해진 하위 도메인으로 제공하고, ACM에서 각각 발급된 인증서를 찾아 변수를 씁니다. 인증서가 없는 구성 요소가 있으면 빠진 것을 나열하고 아무것도 바꾸기 전에 멈춥니다. 아직 admin API와 payments API는 다루지 않으므로 이들의 변수는 직접 설정하세요. 이후 실행에서는 Enter를 눌러 스크립트가 제안하는 루트 도메인을 유지합니다. 비우면 스크립트가 설정한 도메인 변수가 제거됩니다.

```sh
./scripts/setup-stage.sh discava-development
```

| 구성 요소 | 루트가 `example.com`일 때의 도메인 |
| --- | --- |
| Core API | `core-api.example.com` |
| Instructor API | `instructor-api.example.com` |
| 학생 포털 | `example.com`, `www.example.com` |
| 강사 포털 | `instructor.example.com` |
| 관리자 포털 | `admin.example.com` |
| 강의 미디어 | `lesson-media.example.com` |
| 공개 미디어 | `media.example.com` |

다른 도메인은 GitHub 환경의 변수를 직접 설정하세요.

알아 둘 세 가지 규칙:

- **각 API에는 자기 도메인만 정확히 명시한 별도의 인증서가 필요합니다.** 와일드카드도, 다른 API와 공유하는 것도 안 됩니다. 그렇지 않으면 브라우저가 두 API에 연결 하나를 재사용해서 엉뚱한 쪽에서 오류를 받을 수 있습니다.
- **동영상 재생에는 공통 상위 도메인이 필요합니다.** 강의 미디어에 사용자 지정 도메인이 있으면 재생은 API와 강의 미디어가 공유하는 쿠키로 승인되므로, 둘이 하나의 상위 도메인 아래에 있어야 하며 이를 `…_INFRA_LESSON_MEDIA_COOKIE_DOMAIN`으로 지정합니다. 설정 스크립트는 이를 루트 도메인으로 설정합니다.
- **DNS는 직접 관리합니다.** 배포 후 각 도메인을 대상에 연결하세요. 포털과 미디어는 CloudFront 배포(스택 출력 `…DistributionDomainName`), API는 API Gateway 사용자 지정 도메인(해당 API 스택의 출력 `…DomainNameAlias`)입니다. 그때까지는 포털이 이미 그 도메인을 쓰고 있더라도 도메인이 확인되지 않습니다.

포털 도메인은 API가 허용하는 CORS 출처와 Cognito의 로그인 및 로그아웃 주소로 자동 반영됩니다.

## 알림 이메일

이메일은 SES로 발송됩니다. 스테이지의 리전에서 SES에 도메인이나 주소를 검증하세요. 루트 도메인이 있으면 나머지는 설정 스크립트가 처리합니다. 루트가 검증된 SES 도메인 ID가 된 뒤 스크립트를 다시 실행하면 `notifications@<root>`로 이메일을 보냅니다. 다른 발신자를 쓰려면 아래 변수를 직접 설정하세요. 스크립트는 다시 실행해도 직접 설정한 발신자를 유지합니다.

| 변수 | 예시 |
| --- | --- |
| `…_INFRA_NOTIFICATIONS_FROM_ADDRESS` | `notifications@example.com` |
| `…_INFRA_NOTIFICATIONS_SES_IDENTITY` | `example.com` |

둘 다 설정하지 않으면 이메일은 발송되지 않고 각각 건너뜀으로 기록됩니다. 앱 내 알림은 관계없이 동작합니다. 새 SES 계정은 샌드박스에 있어서 AWS가 프로덕션 접근을 승인하기 전까지 검증된 주소로만 보낼 수 있습니다.

## 결제

Stripe는 **배포 시점 구성이 필요 없습니다**. 만들 시크릿도, 등록할 웹훅도 없습니다. 배포 후 관리자가 관리자 포털의 결제 페이지에 Stripe 키를 붙여 넣으면 Discava가 스테이지의 웹훅 주소를 스스로 등록합니다. 단계는 <Link path="guides/payments">유료 강좌와 결제</Link>에 있습니다.

웹훅 API도 위 표의 `…_INFRA_PAYMENTS_DOMAIN_NAME`으로 자체 도메인을 가질 수 있습니다. Stripe를 연결한 뒤 이를 추가하거나 바꿨다면, 새 주소가 등록되도록 결제 페이지에서 키를 다시 저장하세요.

강사에게 지급하려면 Stripe 계정에서 Connect가 활성화되어 있어야 합니다. 제한된 키는 Accounts, Account Links, Login Links, Transfers(정산이 호출하는 것들)에 대한 쓰기 권한이 필요할 것으로 예상되지만, 이 목록은 실제 제한된 키로 아직 확인되지 않았습니다. 온보딩이나 정산이 거부되면 시크릿 키를 사용하세요. 연결된 Stripe 계정이나 모드를 바꾸면 모든 강사의 미지급 수익이 보류됩니다. 보류됨으로 표시되며, 정산 실행은 해당 건을 보내지 않습니다. 강사 쪽 화면은 <Link path="guides/earnings-and-payouts">수익과 정산</Link>에 있습니다.

### 정산 설정

`stages.config.ts`의 스테이지 `payouts` 항목이 플랫폼이 가져가는 몫과 강사에게 지급하는 시점을 정합니다.

| 설정 | 의미 | 기본값 |
| --- | --- | --- |
| `platformFeeBasisPoints` | 결제 금액에 대한 플랫폼 수수료, 베이시스 포인트 단위(2000은 20%). 변경 이후에 기록된 판매에 적용됩니다 | `2000` |
| `holdDays` | 환불에 대비해 판매 수익을 지급 가능해질 때까지 보류하는 일수 | `14` |
| `minimumPayoutMinor` | 보내는 최소 정산액, 통화의 최소 단위(1000은 10.00). 더 작은 잔액은 기다립니다 | `1000` |

`discava-development`는 수익을 하루만 보류하므로, 테스트하는 사람이 금방 지급 가능해지는 것을 볼 수 있습니다. 10000을 넘는 수수료처럼 잘못된 금액을 낼 수 있는 값은 빌드를 실패시킵니다. 정산 실행은 매일 합니다.

## 자막 번역

동영상 자막은 글자 수 단위로 과금되는 Amazon Translate로 기계 번역됩니다. 스테이지의 `captionTranslation` 항목이 그 비용에 한도를 둡니다.

| 설정 | 의미 | 기본값 |
| --- | --- | --- |
| `enabled` | 스테이지가 자막을 번역하는지 여부 | `true` |
| `maxLanguagesPerCourse` | 강좌 하나가 고를 수 있는 최대 자막 언어 수, 0부터 9까지 | `9` |

`discava-development`는 강좌당 세 개 언어를 허용합니다.

## 스테이지 추가

1. `stages.config.ts`의 기존 두 항목 옆에, 완화할 설정을 담아 항목을 추가합니다. 기본값이 맞지 않으면 `payouts`도 추가합니다.
2. 커밋하고 푸시합니다.
3. `./scripts/setup-stage.sh <new-stage>`를 실행해 역할과 GitHub 환경을 만듭니다.
4. 새 스테이지의 이름으로 Deploy 워크플로를 실행합니다.

다른 것은 바뀌지 않습니다. CDK 앱은 파일의 모든 항목마다 스테이지를 만듭니다.

환경 재정의를 쓰는 새 스테이지를 내 컴퓨터에서 배포할 계획이라면, 재정의가 바뀔 때 Nx 캐시가 알아차리도록 `packages/infra/project.json`의 `synth` 타깃 `inputs`에 그 접두사도 추가하세요.

## 프로덕션으로 가기

`discava-production`은 그대로 배포할 수 있습니다. 실제 사용자가 오기 전에:

- 설정 스크립트를 실행하고, 요청받으면 `us-east-1`에서도 CDK를 부트스트랩합니다(WAF 규칙이 그곳에 있습니다)
- 필수 검토자로 <Link path="deploy/setup">GitHub 환경을 보호</Link>합니다
- 사용자 지정 도메인과 검증된 SES ID를 설정합니다
- 예상 트래픽에 비추어 `stages.config.ts`의 요청 제한을 검토합니다
- 강좌를 판매한다면 `payouts` 설정을 검토하고, 관리자 포털의 결제 페이지에서 **라이브** Stripe 키를 연결합니다
