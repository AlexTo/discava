## 1. Deploy 워크플로 실행

포크의 **Actions** 탭에서 **Deploy → Run workflow**를 선택하고, 스테이지 이름을 입력해 실행하세요. 터미널에서 하려면 다음과 같이 합니다.

```sh
gh workflow run deploy.yml -f stage=discava-development
gh run watch
```

첫 배포는 CloudFront 배포 여러 개와 OpenSearch Serverless 컬렉션을 포함한 모든 리소스를 만들기 때문에, 이후 배포보다 훨씬 오래 걸립니다.

### 워크플로가 하는 일

<Steps>

1. **스테이지가 존재하는지 확인합니다.** `stages.config.ts`에서 찾으므로, 오타가 있으면 AWS를 건드리기 전에 실패합니다.

2. **구성 재정의를 전달합니다.** 스테이지의 GitHub 환경(또는 저장소)에서 이름이 스테이지 접두사로 시작하는 모든 변수(`discava-development`라면 `DISCAVA_DEVELOPMENT_`)가 빌드에 전달됩니다. 사용자 지정 도메인이 이렇게 전달됩니다.

3. **Trivy로 스캔합니다.** 수정본이 있는 알려진 치명적 취약점이나 커밋된 시크릿이 있으면 배포가 멈춥니다.

4. **AWS에 로그인합니다.** 단기 OIDC 토큰으로 배포 역할로 로그인합니다.

5. **합성합니다.** CDK로 CloudFormation 템플릿을 만들며, 모든 역할에 스테이지의 권한 경계가 적용됩니다.

6. **배포합니다.** 의존성 순서대로 각 스택을 배포합니다. CloudFormation이 실행 역할로 리소스를 만듭니다. 자동 실행은 그 사이 `main`에 더 새로운 커밋이 생겼다면 이 단계를 건너뜁니다.

</Steps>

## 2. 포털 찾기

각 포털은 CloudFront 배포입니다. 주소는 `Websites` 스택의 출력입니다. AWS CLI를 스테이지의 리전으로 설정한 상태에서 다음을 실행하세요.

```sh
aws cloudformation describe-stacks \
  --stack-name discava-development-Websites \
  --query 'Stacks[0].Outputs[?contains(OutputKey, `DistributionDomainName`)].[OutputKey,OutputValue]' \
  --output table
```

학생, 강사, 관리자 포털 각각의 `*.cloudfront.net` 주소가 하나씩 나옵니다. 학생 포털을 열면 아직 비어 있는 카탈로그가 보여야 합니다.

## 3. 첫 사용자 만들기

사용자는 Cognito 사용자 풀에 있으며, 어느 포털과 API를 쓸 수 있는지는 세 그룹이 결정합니다.

| 그룹 | 사용 가능 |
| --- | --- |
| `student` | 학생 포털 |
| `instructor` | 강사 포털 |
| `admin` | 관리자 포털 |

`discava-development`는 **자체 가입이 꺼져 있어** 낯선 사람이 테스트 스테이지에 계정을 만들 수 없습니다. 사용자는 직접 추가합니다.

<Steps>

1. 스테이지의 리전에서 **Cognito** 콘솔을 열고 스테이지의 사용자 풀을 선택합니다. ID는 `discava-development-Data` 스택의 출력입니다.

2. 이메일 주소와 임시 비밀번호로 **Create user**를 합니다. 비밀번호는 8자 이상이며 대문자, 소문자, 숫자, 기호를 각각 포함해야 합니다. 임시 비밀번호는 3일 뒤 만료됩니다.

3. 사용자를 열고 **Add user to group**을 선택해, 필요한 그룹을 각각 추가합니다. 모든 것을 보려면 본인을 세 그룹 모두에 추가하세요.

4. 이메일 주소로 포털에 로그인합니다. Cognito가 영구 비밀번호를 설정하라고 요청합니다.

</Steps>

`discava-production`은 자체 가입이 켜져 있고 MFA가 필수입니다. 가입한 사람은 `student`와 `instructor` 그룹에 자동으로 추가됩니다. 관리자는 모든 스테이지에서 항상 직접 추가합니다.

## 4. 카테고리 추가

강좌는 관리자가 관리하는 카테고리로 정리됩니다. 관리자 포털에 로그인해 만들거나, 클론한 저장소에서 기본 세트(Science, Technology, Mathematics, Communication, Business)를 쓸 수 있습니다.

```sh
TABLE=$(aws cloudformation describe-stacks --stack-name discava-development-Data \
  --query 'Stacks[0].Outputs[?contains(OutputKey, `CoreTableName`)].OutputValue' --output text)

DISCAVA_DYNAMODB_CORE_TABLE="{\"tableName\":\"$TABLE\"}" pnpm nx run @discava/tooling-deploy:seed-categories
```

셸의 AWS 자격 증명과 리전을 사용하므로 스테이지의 것이어야 하며, 이미 있는 카테고리는 건너뜁니다. `DISCAVA_DYNAMODB_CORE_TABLE`이 없으면 대신 로컬 개발 테이블에 씁니다.

## 5. 처음부터 끝까지 써보기

<Steps>

1. **강사 포털**에서 강좌를 만들고, 동영상이 있는 레슨을 추가하고, 게시합니다. 동영상은 MediaConvert가 트랜스코딩하며 업로드 몇 분 뒤에 재생할 수 있습니다.

2. **학생 포털**에서 강좌를 찾아 수강 등록하고 레슨을 재생합니다.

3. **관리자 포털**에서 카테고리 목록을 확인합니다.

</Steps>

관리자가 관리자 포털에서 배포 없이 설정하는 것이 둘 있습니다.

- 플랫폼의 이름, 로고, 색상: <Link path="guides/branding">브랜딩</Link>
- 강좌를 판매하기 위한 Stripe 계정: <Link path="guides/payments">유료 강좌와 결제</Link>

## 이후 배포

- **자동:** `AUTO_DEPLOY_STAGE`를 설정했다면 CI를 통과한 `main`에 대한 모든 푸시가 그 스테이지를 배포합니다. 그 사이 더 새로운 커밋이 `main`에 도달했다면 배포는 건너뜁니다.
- **수동:** Deploy 워크플로를 다시 실행합니다. 실행한 위치의 커밋을 배포하며, 롤백하는 방법도 이것입니다. 이전 커밋에서 실행하면 됩니다.

한 스테이지에 대한 배포는 겹치지 않습니다. 두 번째 실행은 첫 번째가 끝나기를 기다립니다.

더 새로운 Discava 버전을 가져온 뒤에는 배포하기 전에 <Link path="deploy/setup">설정 스크립트를 다시 실행</Link>해서, 스테이지의 역할이 새 버전이 만드는 것을 허용하도록 하세요.

다음: 사용자 지정 도메인과 이메일로 <Link path="deploy/configuration">스테이지를 구성</Link>하세요.
