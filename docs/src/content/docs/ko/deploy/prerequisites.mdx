## AWS 계정

배포할 AWS 계정이 하나 필요합니다. 시스템을 익히는 동안은 전용 계정, 최소한 다른 중요한 것이 없는 계정이 가장 안전합니다.

스테이지끼리 계정을 공유할 수 있습니다. 각 스테이지는 자체 IAM 역할을 가지며, 한 스테이지의 배포가 다른 스테이지의 리소스에 닿을 수 없습니다.

### 일회성 설정에 필요한 권한

설정 스크립트는 **스테이지마다 한 번, 내 컴퓨터에서, 내 AWS 자격 증명으로** 실행합니다. 이 자격 증명으로 다음을 할 수 있어야 합니다.

- IAM OIDC 공급자, IAM 역할, IAM 관리형 정책 생성
- CDK 부트스트랩(`cdk bootstrap`). S3 버킷, ECR 리포지토리, IAM 역할이 있는 CloudFormation 스택을 만듭니다
- 사용자 지정 도메인을 쓴다면 ACM 인증서 읽기

`AdministratorAccess`면 모두 충족됩니다. 설정이 끝나면 배포는 내 자격 증명이 아니라 스크립트가 만든 범위 제한 역할을 사용합니다.

### 리전

스테이지가 있을 리전을 고르세요. Discava가 쓰는 모든 서비스를 제공해야 하며, 여기에는 **OpenSearch Serverless**, **MediaConvert**, **Transcribe**, **Translate**(자막 번역), 알림 이메일용 **SES**가 포함됩니다. 확실하지 않으면 [AWS 리전별 서비스 목록](https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/)을 확인하세요.

CloudFront의 WAF 규칙은 항상 `us-east-1`에 있습니다. 포털이나 미디어에 WAF가 켜진 스테이지(예: `discava-production`)는 주 리전과 관계없이 그곳에도 작은 스택을 배포합니다.

### 비용

모든 것이 서버리스이며 사용량만큼 과금됩니다. `discava-development`는 0까지 줄도록 구성되어 있어, 유휴 시 비용이 없고 한동안 조용했다가 처음 검색할 때 10~30초 지연이 있습니다. `discava-production`은 작은 검색 용량을 계속 켜 두고 WAF와 KMS 키를 켜며, 이들은 고정 월 요금이 있습니다.

## 내 컴퓨터의 도구

| 도구 | 이유 |
| --- | --- |
| [Git](https://git-scm.com/) | 포크를 클론하려면 |
| [Node.js 24](https://nodejs.org/) | 설정 스크립트가 TypeScript 설정에서 스테이지를 읽습니다 |
| [pnpm](https://pnpm.io/) | 워크스페이스를 설치합니다. `corepack enable`을 실행하면 저장소가 고정한 버전을 받습니다 |
| [AWS CLI v2](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) | 설정 스크립트가 이것으로 IAM 리소스를 만듭니다 |
| [GitHub CLI (`gh`)](https://cli.github.com/) | 설정 스크립트가 GitHub 환경과 변수를 만들 수 있게 합니다. 선택 사항이며, 없으면 스크립트가 값을 출력하므로 직접 입력하면 됩니다 |
| Bash | 설정 스크립트용. macOS에 포함된 bash로 충분합니다 |

설정이나 배포에는 Docker가 **필요 없습니다**. <Link path="guides/getting-started">Discava를 로컬에서 실행</Link>하거나 내 컴퓨터에서 취약점 스캔(`pnpm trivy`)을 돌릴 때만 필요합니다.

### 두 CLI 모두 로그인

```sh
aws sts get-caller-identity   # should print your account and identity
gh auth status                # should say you are logged in
```

첫 번째가 실패하면 `aws sso login --profile <profile>` 또는 `aws configure`로 로그인하세요. 두 번째가 실패하면 `gh auth login`을 실행하세요.

## GitHub 계정

저장소를 포크하고, 포크에서 설정을 바꾸고 워크플로를 실행할 수 있어야 합니다. 공개 포크라면 무료 요금제의 개인 계정으로 충분합니다.

## 선택 사항, 나중에 결정

- **사용자 지정 도메인.** 없으면 포털은 `*.cloudfront.net`에서, API는 `*.execute-api.amazonaws.com`에서 제공됩니다. 직접 도메인을 쓰려면 DNS를 제어하는 루트 도메인과 발급된 ACM 인증서가 필요합니다. 스테이지 리전에서 `core-api.<root>`와 `instructor-api.<root>` 각각 하나씩, `us-east-1`에서 `<root>`와 `*.<root>` 하나입니다. <Link path="deploy/configuration">스테이지 구성</Link>을 참고하세요.
- **이메일.** 알림 이메일에는 검증된 SES ID가 필요합니다. 없으면 이메일은 발송되지 않고 나머지는 모두 정상 동작합니다.
- **결제.** 강좌를 판매하려면 Stripe 계정이 필요합니다. 배포 시점에는 아무것도 필요 없고, 관리자가 나중에 관리자 포털에서 연결합니다.
