이 페이지는 Discava 포크를 내 AWS 계정에 연결합니다. 끝나면 포크에 Deploy 워크플로가 필요한 모든 것이 갖춰지지만, 아직 아무것도 배포되지는 않습니다.

## 1. 포크와 클론

<Steps>

1. GitHub에서 [AlexTo/discava](https://github.com/AlexTo/discava)를 포크합니다. 바꿀 이유가 없다면 이름은 `discava`로 두세요.

2. 원본이 아니라 **내 포크**를 클론합니다. 설정 스크립트는 `origin` 리모트에서 신뢰할 저장소를 읽습니다.

   ```sh
   git clone https://github.com/<you>/discava.git
   cd discava
   ```

3. 의존성을 설치합니다. 설정 스크립트가 스테이지 목록을 읽는 데 필요합니다.

   ```sh
   corepack enable
   pnpm i
   ```

</Steps>

## 2. GitHub에서 포크 준비

포크의 **Settings** 또는 **Actions** 탭에 있는 세 가지 설정입니다.

<Steps>

1. **워크플로 활성화.** GitHub는 새 포크의 워크플로를 비활성화합니다. **Actions** 탭을 열고 **I understand my workflows, go ahead and enable them**을 선택하세요.

2. **GitHub Pages 활성화.** **Settings → Pages**로 가서 **Source**를 **GitHub Actions**로 설정하세요.

   CI 워크플로는 `main`에 푸시할 때마다 이 문서 사이트를 Pages에 게시합니다. Pages가 꺼져 있으면 그 작업이 실패하고, CI가 실패로 표시되며, CI를 기다리는 자동 배포가 시작되지 않습니다. 수동 배포는 어느 쪽이든 동작합니다.

3. **선택 사항: `CODECOV_TOKEN` 추가.** CI는 테스트 커버리지를 Codecov에 업로드합니다. 포크의 커버리지를 보려면 Codecov의 토큰을 **Settings → Secrets and variables → Actions**에서 저장소 시크릿으로 추가하세요.

</Steps>

:::note[문서 사이트의 주소]
CI는 포크의 GitHub Pages 주소 `https://<owner>.github.io/<repository>`에 맞춰 문서 사이트를 빌드하므로 바꿀 것이 없습니다. 사용자 지정 도메인 같은 다른 곳에 게시하려면 저장소 변수 `DOCS_SITE`(예: `https://docs.example.com`)와 `DOCS_BASE_PATH`(예: `/my-lms`, 도메인 루트라면 `/`)를 설정하세요.
:::

## 3. 설정 스크립트 실행

스크립트는 `scripts/setup-stage.sh`입니다. 배포할 스테이지마다 한 번씩 실행하세요.

```sh
./scripts/setup-stage.sh discava-development
```

일련의 질문을 하며, 각 질문에는 감지된 기본값이 있어 Enter로 수락할 수 있습니다. 마지막에 요약을 확인하기 전까지는 아무것도 만들지 않습니다. 다시 실행해도 안전합니다. 각 단계는 없는 것을 만들고 있는 것을 갱신합니다.

### 묻는 내용

순서대로입니다.

| 프롬프트 | 답할 내용 |
| --- | --- |
| **Stage** | 설정할 스테이지. 스테이지는 `packages/common/infra-config/src/stages.config.ts`에서 가져옵니다 |
| **GitHub** | `origin`이 내 포크라면 답할 것이 없습니다. 신뢰할 저장소를 출력하니 내 것인지 확인하세요 |
| **AWS credentials** | 대상 계정의 AWS CLI 프로필, 기본 자격 증명을 쓰려면 비워 둡니다. 로그인한 사용자를 출력합니다 |
| **Region** | 스테이지의 주 리전. `stages.config.ts`에 지정되어 있으면 묻지 않습니다 |
| **CDK bootstrap** | 부트스트랩되지 않았다고 보고된 각 리전에 대해 Yes |
| **GitHub environment** | 스테이지 이름의 환경을 만들고 변수를 설정하려면 Yes. GitHub CLI가 없으면 묻지 않습니다 |
| **Deploy automatically?** | `main`에서 CI가 통과할 때마다 이 스테이지를 배포하려면 Yes. 워크플로를 실행할 때만 배포하려면 No(기본값). 자동으로 배포할 수 있는 스테이지는 하나뿐입니다 |
| **Root domain** | 지금은 비워 둡니다. 나중에 스크립트를 다시 실행해, ACM에서 찾은 인증서로 모든 구성 요소를 그 도메인의 하위 도메인으로 제공할 수 있습니다(<Link path="deploy/configuration">스테이지 구성</Link> 참고) |
| **Continue?** | 요약에 내 저장소, 계정, 리전, 스테이지가 맞게 표시되면 Yes |

### 만드는 것

**AWS**에서:

| 리소스 | 이름 | 용도 |
| --- | --- | --- |
| OIDC 공급자 | `token.actions.githubusercontent.com` | GitHub Actions가 이 계정에 로그인하게 합니다. 모든 스테이지가 공유합니다 |
| 배포 역할 | `github-deploy-<stage>` | Deploy 워크플로가 맡습니다. `<stage>` 이름의 내 저장소 환경만 신뢰합니다. 에셋을 게시하고 스테이지의 CloudFormation 스택을 관리할 수 있습니다 |
| 실행 역할 | `cfn-execution-<stage>` | CloudFormation이 스테이지의 리소스를 만들 때 씁니다. 권한은 인라인 정책 하나와 관리형 정책 셋(`cfn-execution-<stage>-data`, `-edge`, `-compute`)에 있습니다 |
| 권한 경계 | `permissions-boundary-<stage>` | 스테이지가 만드는 모든 IAM 역할이 이것을 달아야 하며, 배포된 스택이 스스로 부여할 수 있는 권한을 제한합니다 |
| Docker 로그인 역할 | `github-docker-login-<repo>` | 내 저장소의 워크플로가 Amazon ECR Public에 로그인해 이미지 가져오기에 속도 제한이 걸리지 않게 합니다. 모든 스테이지가 공유합니다 |
| CDK 부트스트랩 스택 | `CDKToolkit` | CDK에 필요한 에셋 버킷과 역할이며, 동의한 각 리전에 만들어집니다 |

`discava-production`처럼 포털이나 미디어에 WAF가 켜진 스테이지는 `us-east-1`에서도 부트스트랩됩니다.

**GitHub**에서:

| 위치 | 변수 | 값 |
| --- | --- | --- |
| 환경 `<stage>` | `AWS_REGION` | 스테이지의 리전 |
| 환경 `<stage>` | `AWS_DEPLOY_ROLE_ARN` | 배포 역할 |
| 환경 `<stage>` | `AWS_EXECUTION_ROLE_ARN` | 실행 역할 |
| 저장소 | `AWS_DOCKER_LOGIN_ROLE_ARN` | Docker 로그인 역할 |
| 저장소 | `AUTO_DEPLOY_STAGE` | 스테이지 이름. 자동 배포를 선택한 경우에만 |

이들은 **시크릿이 아니라 변수**입니다. 역할 ARN은 민감하지 않습니다. 배포 역할은 내 저장소의 해당 환경에서 실행되는 워크플로만 맡을 수 있고, Docker 로그인 역할은 내 저장소의 워크플로만 맡을 수 있습니다.

### GitHub CLI 없이

`gh`가 설치되어 있지 않거나 로그인되어 있지 않아도 스크립트는 AWS의 모든 것을 만든 다음, 환경과 변수를 출력합니다. **Settings → Environments**와 **Settings → Secrets and variables → Actions → Variables**에서 직접 만들면 됩니다.

### 무인 실행

```sh
AWS_PROFILE=my-profile AWS_REGION=eu-west-1 ./scripts/setup-stage.sh --yes discava-development
```

`--yes`는 모든 기본값을 수락하므로 자동 배포는 켜지지 않습니다. `./scripts/setup-stage.sh --help`는 각 답을 미리 지정하는 환경 변수를 나열합니다.

### 다시 실행해야 할 때

- 사용자 지정 도메인이나 알림 발신자를 추가하거나 바꿀 때(<Link path="deploy/configuration">스테이지 구성</Link> 참고)
- 더 새로운 Discava 버전을 가져온 뒤, 배포하기 전에. 스크립트가 실행 역할과 경계의 권한을 가지고 있어서, 새 종류의 AWS 리소스를 쓰는 버전은 이를 확장합니다. 갱신하지 않으면 배포가 접근 거부 오류로 실패합니다

## 4. 프로덕션 보호

내 포크에서 워크플로를 실행할 수 있는 사람은 누구나 스테이지를 배포할 수 있습니다. `discava-production`이나 실제 사용자가 있는 스테이지는 **Settings → Environments → `<stage>`**를 열어 다음을 하세요.

- **필수 검토자**(required reviewers)를 추가해 배포마다 승인을 기다리게 합니다
- **배포 브랜치**(deployment branches)를 `main`으로 제한합니다

## 결과 확인

```sh
gh variable list --env discava-development
gh variable list
```

첫 번째는 `AWS_*` 변수 세 개를 나열해야 합니다. 두 번째는 `AWS_DOCKER_LOGIN_ROLE_ARN`을, 자동 배포를 선택했다면 `AUTO_DEPLOY_STAGE`도 나열해야 합니다.
