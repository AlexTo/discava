수강생이 강좌를 구매하면 몇 초 안에 내 몫이 기록되고 Stripe를 통해 지급됩니다.

## 수익 계산 방식

판매 건마다 다음과 같이 계산합니다.

> net = amount paid − platform fee

- **amount paid**는 쿠폰 적용 후 수강생이 실제로 결제한 금액입니다. **discount**는 이 금액을 낮추고, 따라서 내 몫도 줄어듭니다. 수익은 정가가 아니라 결제 금액을 기준으로 합니다.
- **platform fee**는 결제 금액에 대한 비율이며 플랫폼이 정합니다(변경하지 않았다면 20%). 판매 건에는 기록 당시의 수수료가 유지됩니다.
- 강좌에 **강사가 여러 명**이면 각 판매 건을 똑같이 나눕니다.
- **refund**는 환불된 금액에 대한 내 몫을 되가져가고 그에 해당하는 수수료를 돌려줍니다. 전액 환불이면 판매 건은 0이 됩니다.

통화는 각각 따로 관리됩니다. 환산은 하지 않습니다.

판매는 결제된 날에, 환불은 환불이 이루어진 날에 집계되므로 지난달 판매 건을 환불하면 이번 달 수치가 줄어듭니다. 날짜는 UTC 기준입니다.

## Earnings 페이지

강사 포털 사이드바의 **Earnings**는 네 부분으로 구성됩니다.

**Payout account**: 상태와 그에 대해 해야 할 한 가지 일. [정산 설정하기](#정산-설정하기)를 참고하세요.

**Balance**, 통화별:

| 수치 | 의미 |
| --- | --- |
| **On hold** | 벌었지만 아직 보류 기간 안에 있음. 페이지에 다음 해제 날짜가 표시됨 |
| **Waiting for account setup** | 보류 기간은 지났지만 활성 정산 계정이 없음 |
| **Ready** | 다음 정산에 포함되어 전송됨 |

**Report**: 처음에는 이번 달이 표시됩니다. 다른 달을 고르거나 **Custom range**를 선택해 최대 366일 간격의 From과 To 날짜를 지정합니다.

- 강좌별로 주문 수, 총액, 할인, 환불, 플랫폼 수수료, 순수익을 보여주며 통화별 합계가 있습니다.
- 강좌의 **Show orders**를 선택하면 각 판매와 환불이 주문 참조와 함께 나열됩니다. 구매자가 누구인지는 표시되지 않습니다.
- 날짜는 UTC 기준으로 계산됩니다.

**Payouts**: 각 정산의 날짜, 금액, 상태.

## 정산 설정하기

1. **Earnings**를 엽니다.
2. **Payout account** 카드에서 **Set up payouts**를 선택합니다.
3. Stripe 자체 페이지에서 신원 정보와 은행 정보를 입력합니다. 마치면 Stripe가 Earnings로 돌려보냅니다.

카드에는 현재 상태가 표시됩니다.

| 상태 | 해야 할 일 |
| --- | --- |
| **Not set up** | **Set up payouts** |
| **In progress** | **Continue setup**: Stripe 양식이 아직 끝나지 않음 |
| **Active** | 할 일 없음. **Open Stripe dashboard**를 선택하면 Stripe 계정으로 이동 |
| **Restricted** | **Fix account**: Stripe가 추가 정보를 요구함 |

카드에 "Payouts aren't available yet"이 표시되면 플랫폼이 Stripe를 연결하지 않은 것입니다. 관리자에게 문의하세요.

정산을 설정했는지와 관계없이 수익은 기록됩니다. 설정할 때까지 대기합니다.

## 지급 시점

- 각 판매 건은 플랫폼이 정한 일수 동안 **보류**됩니다(프로덕션 스테이지에서는 변경하지 않았다면 14일). 따라서 그동안의 환불은 내게서 회수할 필요가 없습니다.
- 정산 실행은 **하루에 한 번** 이루어집니다. 준비된 모든 금액을 통화별로 한 건씩 전송합니다.
- **최소 정산 금액**(변경하지 않았다면 10.00) 미만의 잔액은 이후 실행을 기다립니다.

정산 상태는 다음 중 하나입니다.

- **Pending**: 전송 중입니다.
- **Sent**: Stripe가 수락했습니다.
- **Failed**: Stripe가 사유와 함께 거부했습니다. 해당 수익은 잔액으로 돌아가 다시 시도됩니다.

## 지급 후 환불

판매 건이 정산된 뒤에 환불되면 **음수 잔액**이 남습니다. 다음 정산에서 차감되며, 은행 계좌에서 돈이 빠져나가지는 않습니다.

## 보류된 수익

플랫폼이 결제를 받는 Stripe 계정을 바꾸면, 변경 전에 벌었지만 아직 지급되지 않은 수익은 **Held**로 표시됩니다. "Earned before the platform changed its payment account. Contact the platform to be paid." 정산 계정은 이전 계정에 속해 있었으므로 설정되지 않은 것으로 표시됩니다. 지금부터의 판매를 위해 다시 설정하세요.

## 관리자용

- 정산에는 플랫폼의 Stripe 계정에서 **Connect**가 활성화되어 있어야 합니다. 그렇지 않으면 **Set up payouts**를 선택한 강사에게 "This platform can't set up payout accounts yet"이 표시됩니다.
- 제한된 키는 <Link path="guides/payments">결제 수령</Link>에 필요한 권한 외에도 연결된 계정, 계정 링크, 로그인 링크, 이체를 관리할 수 있어야 합니다.
- 수수료, 보류 기간, 최소 정산 금액은 스테이지별로 설정합니다. 개발 스테이지는 판매를 14일이 아니라 1일 보류합니다. <Link path="deploy/configuration">스테이지 구성</Link>을 참고하세요.
- Stripe 계정이나 모드를 바꾸면 모든 강사의 미지급 수익이 보류됩니다. 먼저 일일 실행이 준비된 금액을 지급하도록 두고, 보류된 수익은 수동으로 지급하세요.

## 제한 사항

- 세금 양식, 인보이스, 세금 계산 기능이 없습니다.
- 통화 환산이 없습니다.
- 분쟁과 차지백은 리포트에 나타나지 않습니다.

작동 방식은 <Link path="design/instructor-payouts">강사 정산</Link>에 설명되어 있습니다.
