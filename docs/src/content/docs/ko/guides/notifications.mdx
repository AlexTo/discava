알림은 한 사람에게 보내는 짧은 메시지입니다. 모든 포털 헤더의 벨 아이콘에 표시되며, 환경설정에 따라 이메일로도 전송됩니다.

## 받는 알림

| 알림 | 전송 시점 | 이메일 |
| --- | --- | --- |
| **Course announcements** | 강사가 내가 속한 강좌에 공지를 게시했을 때 | 켜짐 |
| **Discussion replies** | 레슨 토론에서 누군가 내 게시물에 답글을 달았을 때 | 켜짐 |
| **Answered questions** | 누군가 내 질문의 답변을 채택했을 때 | 켜짐 |
| **Accepted answers** | 내 답글이 답변으로 채택되었을 때 | 꺼짐 |
| **Assignment returned** | 강사가 내 제출물을 반환했을 때 | 켜짐 |
| **Resubmission requested** | 강사가 과제 재제출을 요청했을 때 | 켜짐 |
| **Assignment grade updated** | 강사가 반환된 과제의 점수를 변경했을 때 | 켜짐 |
| **Certificates** | 수료증을 받았을 때, 그리고 LinkedIn 프로필에 추가하라는 알림 한 번 | 켜짐 |
| **Certificate revoked** | 받은 수료증이 취소되었을 때 | 켜짐 |
| **Certificate restored** | 취소된 수료증이 다시 유효해졌을 때 | 켜짐 |
| **Refunds** | 구매한 강좌의 전액 환불이 완료되었을 때 | 항상 |
| **New assignment submissions** (강사) | 수강생이 내 과제에 제출물을 냈을 때, 과제당 하루에 최대 한 번 | 꺼짐 |
| **Course reviews** (강사) | 수강생이 내 강좌에 리뷰를 남겼을 때 | 꺼짐 |

"켜짐"과 "꺼짐"은 기본 설정입니다. "항상"은 끌 수 없습니다.

## 벨 아이콘

벨 아이콘에는 이메일 설정과 관계없이 모든 알림이 나열됩니다. 알림을 선택하면 해당 페이지가 열립니다. **Mark all as read**는 읽지 않은 개수를 지웁니다.

## 이메일 켜기와 끄기

1. 아무 포털에서 계정 메뉴를 열고 **Notification settings**를 선택합니다.
2. 알림 옆의 스위치로 이메일로도 받을지 선택합니다.

모든 이메일에는 구독 취소 링크도 있습니다. 링크는 수강생 포털의 페이지를 열며, 여기서 **Stop these emails**를 누르면 해당 종류의 이메일이 꺼지고, 누르기 전에는 아무것도 바뀌지 않습니다. **Turn them back on**으로 되돌립니다.

이 페이지의 나머지는 기능에 알림을 추가하는 개발자를 위한 내용입니다. 기능은 `@discava/core-table`의 헬퍼를 통해 알림을 게시합니다. 알림 레코드는 다른 어떤 것도 쓸 수 없습니다.

## 이벤트 타입 추가

각 알림 종류는 `NOTIFICATION_TYPES`(`packages/databases/core-table/src/helpers/notification-types.ts`)의 항목 하나입니다.

- `id`: 안정적인 `<area>.<event>` 형식, 예를 들어 `announcement.posted`.
- `name`과 `description`: 설정 페이지에 표시되는 내용.
- `params`: 알림을 구성하는 평면 문자열 파라미터.
- `emailPolicy`: `default-on`, `default-off`, `required`(항상 전송) 또는 `never`(벨 아이콘만).
- `build(params)`: 순수 함수이며 `title`(120자로 자름), `body`(500자로 자름), `link`(`portal`과 `/`로 시작하고 비밀 값을 포함하지 않는 `path`)를 반환합니다. 선택 사항인 `action`(`label`과 `path`, link와 같은 포털)을 하나 반환할 수도 있습니다. 이메일에는 두 번째 버튼과 줄로 표시되고 벨 아이콘은 무시합니다.
- `emailPreferenceType`(선택 사항): 이 타입의 이메일 설정, 구독 취소 토큰, 설정 레이블을 관장하는 다른 타입의 id. 이 타입에는 자체 설정이 없으며 `setNotificationPreference`는 이를 거부하고 설정 페이지에서도 제외됩니다. `isEmailEnabled`가 이를 해석합니다.

수료증용 타입은 네 가지입니다. `certificate.issued`(`link`는 수료증 페이지이고 `action`은 "Add to LinkedIn profile"), `certificate.reminder`(같은 link와 action이며 `emailPreferenceType: 'certificate.issued'`), `certificate.revoked`와 `certificate.restored`(둘 다 My Learning으로 연결). <Link path="design/certificates">수료증</Link>을 참고하세요.

`order.refunded`는 구매의 전액 환불이 완료되었음을 수강생에게 알립니다(`link`는 강좌 페이지이고 이메일은 `required`). 수강생이 요청했든 운영자가 대시보드에서 했든 Stripe에서 기록된 모든 전액 환불에 대해 전송되며, 중복 방지 키는 주문 ID이므로 같은 전달이 반복되어도 한 번만 전송됩니다. <Link path="design/payments">결제</Link>를 참고하세요.

`notification-types.test.ts`에 해당 항목의 테스트를 추가하세요. 다른 것은 바꿀 필요가 없습니다. 설정, 벨 아이콘, 이메일이 자동으로 반영합니다.

## 게시

모든 헬퍼는 같은 입력을 받습니다. `type`, `params`, `dedupeKey`, `occurredAt`, 그리고 `userId`(강좌 대상이면 `courseId`)입니다.

- `notificationWrites(service, input)`는 입력을 검증하고 트랜잭션 항목(알림과 사용자의 읽지 않은 개수)을 반환합니다. 알림 대상이 되는 쓰기 옆에서, 직접 작성한 `service.transaction.write`에 추가하면 둘 다 커밋되거나 둘 다 커밋되지 않습니다. 취소된 트랜잭션은 다른 조건 실패와 같이 처리됩니다.
- `publishNotification(service, input)`는 자체 트랜잭션에서 같은 일을 하고 `'created'` 또는 `'duplicate'`를 반환합니다. 알림이 다른 쓰기의 일부가 아닐 때 사용합니다.
- `notifyCourseStudents(service, input)`는 강좌에 등록한(탈퇴하지 않은) 모든 수강생에게 알리도록 요청하는 항목 하나를 반환합니다. 이를 트랜잭션에 추가하세요. 그러면 파이프라인이 `dedupeKey`로 각 수강생의 알림을 만들므로 재시도해도 안전합니다. 수강생만 대상이며, 강사에게는 각각 `notificationWrites`를 호출하세요.

잘못된 입력(등록되지 않은 타입, 누락된 파라미터, 빈 키, 잘못된 시점)은 아무것도 읽거나 쓰기 전에 `NotificationInputError`를 던집니다. 헬퍼는 사용자가 존재하는지, 이메일 주소가 있는지 확인하지 않습니다.

`markNotificationRead`, `markNotificationsRead`, `notificationEmailTransitions`는 호출하지 마세요. API와 전달 기능의 몫입니다.

## 중복 방지 키와 `occurredAt`

중복 방지 키는 이벤트의 이름이며, 예를 들어 `${contentItemId}:${version}`입니다. 알림의 id는 타입과 키에서 만들어지므로 같은 이벤트를 두 번 게시해도, 재시도든 동시에 열 번의 요청이든 알림은 하나입니다. 이벤트가 재시도될 때마다 같고 새 이벤트마다 다른 값을 사용하세요. 무작위 값이나 현재 시각은 안 됩니다.

`occurredAt`은 밀리초가 포함된 UTC ISO 시점(`2026-11-18T21:55:47.000Z`)이며, 코드가 실행된 시점이 아니라 (게시물이 만들어진 때처럼) 자체 레코드에서 가져옵니다. 그래야 재시도해도 같은 값이 나옵니다. 벨 목록의 순서를 정합니다.

## 환경설정과 구독 취소

각 포털의 사용자 메뉴에서 **Notification settings**를 열어 타입별 이메일을 끌 수 있습니다. `required` 타입의 스위치는 켜져 있으며 바꿀 수 없습니다. `never` 타입은 이메일을 보내지 않으며 목록에 나타나지 않습니다. 벨 아이콘은 환경설정의 영향을 받지 않습니다.

모든 이메일에는 변경할 수 없도록 서명된 구독 취소 링크와, 메일 클라이언트의 원클릭 버튼을 위한 `List-Unsubscribe` 헤더가 있습니다. 링크는 수강생 포털의 페이지를 열며, 버튼을 누르기 전에는 아무것도 바꾸지 않고 이메일을 다시 켤 수도 있습니다. 서명 비밀 값은 스테이지별로 Data 스택이 생성합니다.

## 로컬에서 시도하기

`pnpm dev`가 실행 중일 때 `notify-local` 타깃으로 게시합니다.

```sh
pnpm nx run @discava/tooling-local-dev:notify-local -- --user <sub> --type announcement.posted
pnpm nx run @discava/tooling-local-dev:notify-local -- --course <courseId> --type announcement.posted
```

같은 `--key`로 명령을 반복하면 중복이 아무 일도 하지 않는 것을 볼 수 있습니다. 이메일은 내 컴퓨터를 벗어나지 않으며 `http://localhost:2024/inbox`의 로컬 받은편지함에 보관됩니다(`GET /emails`는 JSON으로 나열). `reset-local-data`가 이를 비웁니다.

## 스테이지의 이메일

이메일은 Amazon SES로 전송되며 스테이지를 구성하기 전까지는 꺼져 있습니다. 스테이지 구성의 `infra.notifications` 아래(또는 `<STAGE>_INFRA_NOTIFICATIONS_*` 환경 변수 재정의)에 다음을 설정합니다.

- `fromAddress`: 이메일을 보내는 주소.
- `sesIdentity`: 전달 함수가 보낼 수 있는 검증된 SES 도메인 또는 주소이며 그 외에는 허용되지 않습니다. `fromAddress`가 여기에 속해야 합니다.

`fromAddress`가 없으면 알림은 벨 아이콘에는 계속 도달하고 각 이메일은 건너뜀으로 기록됩니다. SES 샌드박스에서는 수신자도 검증되어야 합니다. 실패한 전달은 알람이 있는 `notification-delivery` 실패 큐로 갑니다.
