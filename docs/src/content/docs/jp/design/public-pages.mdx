コースのランディングページ(`/learn/<courseId>`)と講師のプロフィール(`/instructors/<handle>`)は公開されており、誰でもサインインせずに開けます。受講者ポータルはシングルページアプリなので、スクリプトを実行しないクローラーやリンクプレビューには、空のシェルしか見えません。**ページレンダラー**は、これらのアドレスに本物の HTML を返すことでこれを解決します。

## ページレンダラー

レンダラーは `@discava/core-api` にある2つ目の Lambda ハンドラー(`src/page-renderer/handler.ts`)です。受講者ポータルの CloudFront ディストリビューションは、`/learn/*`、`/instructors/*`、`/certificates/*`、`/sitemap.xml`、`/robots.txt` のオリジンとしてこれを使います。Websites スタックの `StudentPortal` コンストラクトが構築し、CloudFront だけが呼び出せる Function URL を持ちます。応答するのは `GET` と `HEAD` だけです。

ローカルでは、`pnpm dev` がポート 2026 で起動します(`src/local-page-renderer.ts`)。ブラウザは引き続き Vite サーバーを使い、クローラー向けの応答はこのポートから取得されます。

| パス | 応答 |
|---|---|
| `/learn/<courseId>` | 公開済みコースのランディングページ。それ以外は `404` |
| `/learn/<courseId>/<anything>` | `noindex` 付きのそのままの `index.html`(サインイン後の学習ルート)。何も読み取らない |
| `/instructors/<handle>` | 公開済みコースを教えている講師のプロフィール。それ以外は `404` |
| `/certificates/<ID>` | リンクプレビュー用の head(受講者、コース、日付、プラットフォーム名)。常に `noindex`。不明な ID は `404` |
| `/certificates/<ID>/<anything>` | `noindex` 付きのそのままの `index.html`(LinkedIn のルート) |
| それ以外 | `404` |
| `/sitemap.xml` | 公開済みのすべてのコース、公開プロフィール、有効なカテゴリー。`lastmod` 付き |
| `/robots.txt` | [インデックス設定](#インデックス設定)を参照 |

ページについては、レンダラーはビルド済みの `index.html` を取り、次を追加します。

- head タグ: タイトル、説明、正規アドレス、Open Graph と Twitter カードのタグ、schema.org の JSON-LD(`Course`、または `Person` を持つ `ProfilePage`)
- `#root` 内の静的なレンダリング: タイトル、画像、主要な情報、学習成果、受講要件、説明、カリキュラムの概要、評価のまとめ、レビューの最初のページ、講師カード
- 使用したプロシージャの出力を保持する `<script type="application/json" id="discava-page-data">` 要素
- プラットフォームのブランド: アイコン、色、ブランドドキュメント。これにより、ページは最初の描画から管理者が設定したブランドで表示されます(<Link path="design/branding">ブランディング</Link>を参照)。ブランドを読み取れない場合、ページはデフォルトのブランドで描画されます。

起動時に、ポータルは page-data 要素を読み取って削除し、その内容で React Query を初期化します(`src/lib/page-data.ts`)。これにより、アプリの最初の描画は完全なページになり、静的なマークアップを置き換えるときにちらつきません。すべてのテキストは HTML エスケープされ、JSON は `<`、`>`、`&` をエスケープしてシリアライズされるため、コースのタイトルがページから抜け出すことはできません。

**何が公開かの情報源は1つ。** レンダラーは、匿名コンテキストで `appRouter.createCaller` を通し、`course.publicView`、`review.summary`、`review.list`、`instructorProfile.publicView`、`certificate.verify` をインプロセスで呼び出します。そのため、クローラーが API の返す以上のものを見ることはありません。下書きのコース、アーカイブされたコース、不明な ID は、バイト単位で同一の `404` ページになります。これは、そのコースに受講登録している受講者を含め、全員に当てはまります。My Learning を通じた受講者のアクセスは変わりません。

**正規アドレス**は閲覧者のホストを使い、CloudFront Function がそれを `x-discava-host` にコピーします。ホストが使われるのは、そのステージの受講者ポータルのドメインのいずれか(何も設定されていない場合は `*.cloudfront.net` のホスト)である場合だけです。それ以外のホストは、最初に設定されたドメインにフォールバックするため、ドメインをディストリビューションに向けても正規アドレスを汚染できません。

**依存先が失敗した場合**(テーブル、設定パラメーター、`index.html` の読み取り)、応答は `Cache-Control: no-store`、`X-Robots-Tag: noindex`、`Retry-After: 5` を付けたプレーンテキストの `503`(`Service temporarily unavailable`)です。これがキャッシュされることも、`404` に変換されることもありません。HTML を持たないため、障害中にランディングページやプロフィールを読み込んだ訪問者には、アプリではなくそのテキストが表示されます。アプリ内のナビゲーションはレンダラーを通らないため、動き続けます。

## キャッシュと鮮度

CloudFront は各応答をキャッシュします。

| 応答 | `Cache-Control` |
|---|---|
| ページまたはシェル | `max-age=0, s-maxage=300`: CloudFront は5分間保持し、ブラウザは常に再検証する |
| 見つからない場合 | `max-age=0, s-maxage=60` |
| `sitemap.xml`、`robots.txt` | `max-age=300, s-maxage=300` |
| `503` | `no-store` |

キャッシュキーはパスだけです。クエリ文字列、Cookie、`Authorization` ヘッダーは転送されないため、応答が誰が尋ねたかに依存することはありません。

これにより、古さは無効化なしで**5分**に抑えられます。コースやプロフィールの変更は5分以内にクローラーとリンクプレビューに届き、アーカイブされたコースや公開されなくなったプロフィールも、同じ時間内に `404` を返し始めます。ブラウザの訪問者は、アプリが API を読むため、次の読み込みで変更を目にします。

レンダラーは、キャッシュミスのたびに条件付きの `GetObject`(`If-None-Match`。通常は `304`)でポータルの `index.html` を確認し、古いコピーにフォールバックすることはありません。ポータルのデプロイでは、古いハッシュ付きアセットを削除したあと、ディストリビューション全体を無効化するため、キャッシュされたページが存在しなくなったバンドルを指し続けることはありません。

## シングルページアプリの書き換え

デフォルトビヘイビアーの CloudFront Function(共有の `StaticWebsite` コンストラクト内の `spa-rewrite.js`)は、最後のセグメントにファイル拡張子がないパスを `/index.html` に書き換えます。存在しないアセットには S3 のエラーが返され、レンダラーの `404` は閲覧者に届きます。3つのポータルすべてが、この共有コンストラクトからこれを得ています。

ディストリビューションには、`404` や `403` を `200` の `/index.html` に変えるエラー応答はありません。そうした設定はディストリビューションのすべてのオリジンに適用されるため、レンダラーの `404` が成功ページに変わってしまい、検索エンジンにソフト 404 として扱われるからです。

## インデックス設定

`studentPortal.allowSearchEngineIndexing` はステージごとの設定で、デフォルトは `false`、`discava-production` だけが `true` です。(「indexing」だけの名前にしないのは、ここではそれが OpenSearch のインデックス作成をすでに意味しているからです。)

| | 設定がオフ(他のすべてのステージ、ローカル開発) | 設定がオン(本番) |
|---|---|---|
| ページ | レンダラーのすべての応答に `<meta name="robots" content="noindex">` と `X-Robots-Tag: noindex` | `noindex` は見つからない場合の応答と、ランディングページ以外の `/learn/*` シェルだけ。`/certificates/*` は常に `noindex` |
| S3 からのファイル | レスポンスヘッダーポリシーが `X-Robots-Tag: noindex` を追加 | マーカーなし |
| `/robots.txt` | `Disallow: /` | `/learn/*/`、`/my-learning`、`/signin`、`/search` を禁止し、残りを許可して、サイトマップを列挙 |

クローラー向けのコンテンツとソーシャルカードはすべてのステージで提供されるため、本番の前にテストできます。

サイトマップは、リクエストごとにキー指定の読み取りと宣言済みのインデックスから構築され、スキャンは決して行いません(`helpers/sitemap.ts`)。1つのファイルで、サイトマッププロトコルは 50,000 URL までに制限しています。それを超える場合のサイトマップインデックスは今後の課題です。

## プレビュー動画の公開ルール

コースには、講師が専用のファイルとしてアップロードした、5分以内のプレビュー動画を1本置けます。レッスン動画と同じようにトランスコードされ、字幕が付けられ、差し替えると、新しいバージョンの準備ができるまで前のバージョンが再生され続けます。そのレコードである `coursePreview` は `course` とは別なので、トランスコードや字幕のステータスが変わっても `course.updatedAt` は動かず、検索の再インデックスも起きません。

誰でも、サインインしているかどうかにかかわらず再生できますが、次のルールの範囲内に限られます。

- `course.previewVideoUrl` は公開されており、コースが**公開済み**で、プレビューに**再生可能なバージョン**がある間だけ応答します。それ以外では、存在しないコースと同じ動作になります。
- 設定される署名付き Cookie は、**そのバージョンのフォルダーだけ**(レンディションと字幕トラック)を対象とし、有効期間は受講登録した受講者と同じです。レッスン動画、ファイル、その他のコースのコンテンツが、受講登録なしに到達可能になることはありません。
- アーカイブされたコースは、プレビューの提供をただちに止め、復元されれば再び再生します。差し替えられた、または削除されたバージョンは新しいアドレスを発行せず、そのファイルはレッスン動画と同様に後で削除されます。
- このプロシージャは `PUBLIC_OPERATIONS` に含まれているため、公開リクエストの制限と、有効な場合はそのステージのウェブファイアウォールが適用されます。

## 無料プレビューレッスン

講師は、通常のレッスンを無料プレビューとして指定できます。すると誰でも、サインインしているかどうか、受講登録しているかどうかにかかわらず、`/learn/<courseId>/preview/<lessonId>` でそれを開けます。これは、「未払いのユーザーは有料コンテンツを得られない」に対する、意図的な唯一の例外です。

**指定。** レッスンには任意の `freePreview` 属性があり、`true` としてのみ保存され、指定を外すと削除されます(instructor-api の `lesson.setFreePreview`)。この属性を持てるのは種類が `lesson` のレッスンだけです。課題レッスンは指定できず、指定されたものは `free-preview-on-ordinary-lesson` テーブル不変条件が検出します。

レッスンが**公開**プレビューとなるのは、`isOpenFreePreview`(`@discava/core-table` 内)が成り立つときです。この関数が「公開」の唯一の定義です。

- コースが公開済みであること
- モジュールとレッスンが表示されていること(表示状態でアーカイブされていない)
- レッスンが通常のレッスンで、指定されていること

**専用の3つの公開オペレーション。** `freePreview.lesson`、`freePreview.videoUrl`、`freePreview.fileUrl` は core-api の公開クエリで、`PUBLIC_OPERATIONS` に含まれています。呼び出し元を決して読まないため、サインインしていない訪問者、受講登録していないユーザー、受講登録済みの受講者に、同じ応答が返ります。

受講登録が必要なプロシージャ(`course.view`、`contentItem.videoUrl`、`contentItem.fileUrl`、`quiz.view`、進捗、完了、課題、ディスカッションのプロシージャなど)には手を加えておらず、指定されたレッスンでも他のレッスンと同じく受講登録が必要です。公開オペレーションにはクレームがないため、1つのオペレーションで訪問者と受講登録済みの受講者の両方に対応することはできません。

**応答の内容。** 各アイテムはフィールドごとに組み立てられるため、名前を挙げたもの以外は外に出ません。

| アイテム | 訪問者が得るもの |
|---|---|
| 動画 | タイトル、説明、長さ、現在再生できるかどうか |
| テキスト | 本文 |
| ファイル | 名前、サイズ、種類 |
| クイズ | タイトルと問題数だけで、ロックされたカードとして表示。問題、回答キー、設定は含まれない |
| 課題 | 除外される |

ストレージキー、ステータス、ジョブの属性は返されません。公開プレビューではないレッスン、またはその下に表示されていないアイテムを指定した呼び出し元には、理由にかかわらず同じ `NOT_FOUND` が返り、何も署名されません。

**署名。**

- 動画の Cookie はそのバージョンのフォルダーだけを対象とし、その `Path` で設定され、有効期間は**1時間**(`FREE_PREVIEW_COOKIE_LIFETIME_SECONDS`)です。受講登録した受講者は4時間です。
- ページは、訪問者が再生を押したときにアドレスを要求し、動画の再生中は30分ごとに再度要求して、Cookie を更新します。
- ファイルのリンクは1つのオブジェクトを5分間対象とします。テキストには署名は不要です。
- この1時間が、`RETIRED_VERSION_DELAY_MINUTES` がすでにカバーしている Cookie の有効期間を超えることはないため、差し替えられたバージョンのファイルは、すべてのプレビュー Cookie より長く残ります。これはユニットテストで固定されています。

**指定を外すとどうなるか。** オペレーションはリクエストのたびにレッスンを読み取り、何もキャッシュしません。書き込みの後の最初のリクエストから(またはレッスン、そのモジュール、そのコースが非表示またはアーカイブされた後)、3つすべてが `NOT_FOUND` を返します。新たなアクセスは得られません。共有されたプレビューのアドレスには "This preview is no longer available" と表示されます。

**指定を外してもできないこと。** すでに渡したものを取り消すことはできません。

- 動画の Cookie は有効期限まで、発行から最長1時間は動き続け、更新されることはありません。
- ファイルのリンクは最長5分間動きます。
- 画面上のテキスト、ダウンロードされたファイル、録画は取り消せません。

ページレンダラーがキャッシュするため、ランディングページには最大5分間、"Free preview" ラベルが表示され続けることがあります。

**何も記録されない。** プレビューは書き込みを行わず、呼び出し元について何も読み取りません。完了、進捗、保存された動画の再生位置、クイズの受験、受講者のアクティビティ数はなく、ディスカッションもありません。動画は訪問のたびに最初から始まります。これにより、受講者のすべてのレコードが受講登録に結び付いたままになります。`student-records-enrolled` が、すべての e2e テストの後でこれを確認します。

**有料コンテンツのルール。** このルールのデータとしての形である `paid-course-enrolment-paid` は変わりません。プレビューは受講登録を作成しません。API としての形は `paid-access.test.ts` でテストされています。これは、サインイン済みで未登録のユーザーとして、価格が設定されたコースに対してすべてのコンテンツのプロシージャを実行し、さらに公開プレビューレッスンに対しても実行して、同じ `FORBIDDEN` の拒否を確認します。公開プレビューレッスンは名前の付いた唯一の例外で、そのテストは `procedures/free-preview.test.ts`(対象が公開プレビューではないあらゆるパターンの拒否マトリクス)にあります。

**クローラー。** レンダラーは、ランディングページの概要で各公開プレビューレッスンに印を付けます。タイトルがプレビューのアドレスにリンクし、その後に "Free preview" が続きます。レッスンの内容はクローラー向けには描画されません。プレビューのアドレス自体には `noindex` 付きのそのままのページが返され、`robots.txt`(`/learn/*/`)で禁止されており、サイトマップにも含まれません。テキストを描画すると、指定されていないレッスンが検索エンジンのキャッシュで読めてしまうからです。

**運用者向けの注記: 帯域。** プレビュー動画の配信費用はプラットフォームが負担し、1つの署名で1時間ストリーミングできます。公開スロットルが制限するのは署名が発行される頻度であり、1つの署名がストリーミングするバイト数ではなく、プロモーション動画と同じく、誰でもプレビュー動画をストリーミングできます。メディアディストリビューション(メディアバケットの前段にあるディストリビューションで、CloudFront コンソールまたは CloudWatch で確認)の CloudFront データ転送メトリクスと、core API のゲートウェイステージの `freePreview.*` メソッドに対する 429 の件数を監視してください。訪問者ごとのレートルールや、コースごとに指定できるレッスン数の上限は、今後の課題として考えられます。

## プロフィールとハンドル

講師のプロフィールは、最初のコースと一緒に作成されるため、講師カードには常にリンク先があります。`course.create` は、コース自身のトランザクションの直前に `ensureInstructorProfile`(`@discava/core-table` 内)を呼び出します。これは冪等で、コースのないプロフィールがあっても不変条件は壊れません。

- URL には、アカウント ID ではなく**ハンドル**を使います。小文字の英字、数字、単独のハイフンで3〜30文字です。カテゴリー名と同様に、クレームレコード(`profileHandleClaim`)を通じて講師間で一意になります。
- プロフィールが公開されるのは、その所有者が公開済みのコースを少なくとも1つ教えている場合に限り、そのコースだけが一覧されます。オプトアウトはありません。
- 公開される出力には、メールアドレスもアカウント識別子も含まれません。

講師側については、<Link path="guides/instructor-guide">講師ガイド</Link>を参照してください。
