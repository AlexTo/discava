**Spec:** [`specs/20261122-090054-admin-branding/`](https://github.com/AlexTo/discava/tree/main/specs/20261122-090054-admin-branding/)

管理者は管理ポータルからロゴ、名前、アイコン、共有画像、色を設定でき、すべてのポータルと公開ページに5分以内に反映されます。デプロイは不要です。このページでは、その仕組みを説明します。

## レコードとそのリビジョン

ブランドは、core テーブルにある1件の `platformBrand` レコードで、キーは固定です。最初の保存までは存在せず、存在しないことはデフォルトのブランドを意味します。書き込み元は `helpers/platform-brand.ts` の `saveBrand` だけです。

保存のたびに、ブランド全体と、管理者が読み込んだ `revision` が送られます。

- 最初の保存はレコードが存在しないことを条件とし、以降の保存は `revision` が読み込んだ値のままであることを条件とします。
- 条件が満たされない場合は `CONFLICT`（"Someone else changed the branding. Reload to see their changes."）になるため、古い保存が中途半端に適用されることはありません。
- `changedBy`、`changedByName`、`changedAt` フィールドが、最後に保存した人を示します。

## 画像と不変キー

画像は公開メディアバケットの `brand/<kind>/<nonce>.<ext>` に置かれます。`kind` は `logo`、`icon`、`share-image` のいずれかです。`branding.createUploadUrl` は、正確なコンテンツタイプ、長さ、1年間不変の `Cache-Control`、タグ `lifecycle=unattached` を指定した `PUT` の署名付き URL を発行します。新しいアップロードは新しいキーになるため、ブランドが別の画像を指した後に、置き換えられた画像がキャッシュから配信されることはありません。

`branding.save` は、新しく参照されたオブジェクトを読み、その種類、サイズ、形を `@discava/common-branding/image-rules` のルールに照らして確認します（管理ポータルはアップロード前に同じルールを実行します）。保持するオブジェクトからはタグを外し、置き換えられたオブジェクトにはタグを戻します。タグが付いたオブジェクトは、バケットのライフサイクルルールによって1日後に削除されます。いずれかの画像が検証に失敗した場合は、何も書き込まれません。

### SVG のチェック

SVG のロゴは解析され（admin-api の `helpers/brand-image.ts`）、すべての要素と属性が許可リストに載っていない限り拒否されます。`script`、`foreignObject`、`iframe`、イベントハンドラ属性、同一ドキュメントの `#fragment` 以外の参照は使えません。書き換えずに拒否することで、保存されるファイルはアップロードされたものと完全に同じになります。ロゴは `<img>` を通して表示され、ブラウザは `<img>` 内の SVG スクリプトを実行しません。また、ファイルを直接開いた場合に備えて、ディストリビューションが `sandbox` を指定した `Content-Security-Policy` を付与します。iOS のホーム画面アイコンはラスター画像でなければならないため、アイコンは PNG のみです。

## 公開ドキュメント

ブラウザはテーブルを読みません。`brand-publishing` ストリーム機能（[ルーター](./stream-event-router/)を参照）は、ストリームイメージではなく現在のレコードを読むため、配信が遅れても古いリビジョンが公開されることはありません。この機能は、公開メディアバケットに `Cache-Control: public, max-age=60, s-maxage=240` を付けて `brand/brand.json` を置きます。ドキュメントには、誰がいつ保存したかは含まれません。ポータルは別のオリジンから取得するため、ディストリビューションは `brand/` 配下のすべてに `GET` と `HEAD` の CORS ヘッダーを付与します。

これが**キャッシュ予算**です。ブラウザはドキュメントを最大60秒、CloudFront は最大240秒保持するので、変更は新しいページ読み込みのすべてに5分以内に届きます。ドキュメントが存在しない、読めない、または無効な場合はデフォルトのブランドが使われるため、障害でページが壊れることはありません。

## ポータルでの動作

`@discava/common-web-utils/brand` の `BrandProvider` は、各ポータルの `RuntimeConfigProvider` の内側にあり、`useBrand()` が解決済みのブランドを返します。最初に使うのは、ページレンダラーが埋め込んだブランドです。それがなければ最後に見たブランド（`localStorage` に保持）、それもなければ何も使いません。ブランドがある場合はすぐに描画し、バックグラウンドで更新します。ない場合は、`brand.json` が届くか1秒経つまで最初の描画を保留します。CSS 変数、アイコンのリンク、テーマカラー、タイトルを設定します。管理ポータルは `branding.get` と各保存からも値を受け取るため、管理者は変更をすぐに確認できます。

## ページレンダラー

[ページレンダラー](./public-pages/)は、描画のたびにレコードを読み（その後ページは300秒キャッシュされます）、タイトルの接尾辞、`og:site_name`、JSON-LD のプロバイダー、`og:image` と `twitter:image`（ページに独自の画像がない場合は共有画像）、アイコンのリンク、インラインの `:root` スタイルに適用します。また、ポータルがそこから開始できるよう、ブランドドキュメントをページデータに埋め込みます。読み取りに失敗した場合は、警告をログに出してデフォルトのブランドで描画します。

## カラーパレット

`@discava/common-branding/colour` の `brandPalette(hex)` は、上書きする CSS 変数を返します。`--primary`、`--primary-foreground`、`--ring`、サイドバー用の同等の変数、`--brand-link` です。ブランドカラーに対する WCAG コントラスト比が高いほうの文字色を選び、どちらも 4.5:1 に達しない場合はその色を拒否します。`--brand-link` は、ページの背景に対して 4.5:1 に達する場合にのみブランドカラーになります。同じ関数が admin-api、管理ポータルのプレビュー、各ポータル、レンダラーで動くため、結果が食い違うことはありません。意味を持つ色（破壊的操作、チャート、ステータス）は変更されません。

## ブランドが適用されないもの

Cognito のホスト型サインインページとドキュメントサイトは、独自の見た目のままです。
