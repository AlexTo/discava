## 共通の概念

**カリキュラムの階層。** コースはモジュールを含み、モジュールはレッスンを含み、レッスンは順序付きのコンテンツ項目（動画、テキスト、ファイル、クイズ、課題）のリストを含みます。この4つはすべて、ElectroDB の `curriculum` コレクションを通じて1つの DynamoDB パーティション（`COURSE#<courseId>`）に置かれるため、コース全体が1回のクエリで取れます。コースのカリキュラムは DynamoDB の1ページあたり1 MB を超えることがあるため、このクエリはすべてのページを読みます。

**有効な可視性。** モジュール、レッスン、コンテンツ項目が受講生に表示されるのは、**それ自身とすべての祖先**が `visible` でアーカイブされていない場合だけです。受講生の読み取り、受講生の書き込み、進捗の計算はすべて、レコード自身の `visibility` だけではなく、有効な可視性を使います。このルールは `@discava/core-table` の `filterEffectivelyVisible` として1か所で実装されています。

**受講登録。** 受講生がコースの内容を読み、そこに何かを書き込めるのは、受講登録している間だけです。つまり、`status` が `dropped` ではない `enrolment` レコード（pk は `courseId`、sk は `userId`）を持っている場合です。受講生は core-api の `course.enrol` で自分で登録でき、対象は**公開済み**で**無料**のコースだけです。コースの status と価格は受講登録の書き込みと同じトランザクションで確認されるため、リクエストの途中でアーカイブされたり価格が付いたりしたコースが、新しい受講登録を受け付けることはありません。有料コースには、支払い済みの注文によってのみ入れます（<Link path="design/payments">決済</Link>を参照）。再度登録すると、既存の受講登録が返されます。下書きまたはアーカイブされたコースは、匿名の `course.publicView` と同様に `NOT_FOUND` を返すため、下書きの存在は漏れません。受講登録中の受講生は、コースがアーカイブされた後も読むことはできますが、その場合は受講生にとっても読み取り専用です。`course.myEnrolment` は、呼び出し元の受講登録を返します。なければ何も返しません。

**受講生のデータはユーザーをキーにします。** `progress`、`itemCompletion`、`quizAttempt`、`quizSummary` は `userId` をパーティションキーにするため、「あるコースでの受講生の進捗」は1回のクエリで取れます。裏を返せば、「どの受講生がこの項目に触れたか」は、スキャンなしには答えられません。そのため、コンテンツ項目は `studentActivityCount` を持っています。
