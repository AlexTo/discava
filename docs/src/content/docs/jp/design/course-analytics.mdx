講師ポータルのダッシュボードにはコースごとに1枚のサマリーカードが表示され、各カードからそのコースの分析ページを開けます。どちらも、core テーブルのストリームから最新の状態に保たれている保存済みの数値を読みます。リクエスト時にレコードから集計することはないので、受講生が何人いてもページは素早く読み込まれます。

ポータルは、instructor-api の `analytics.courseSummaries`（カード）、`analytics.course`、`analytics.quiz`、`analytics.videoQuestions` を通じてこれらを読みます。

## 定義

| 数値 | 定義 |
|---|---|
| **Enrolments** | コースにこれまでにあったすべての受講登録（退会した受講生を含む）。履歴チャートでは、受講生が登録した UTC の日に1件ずつ数えます |
| **Dropped** | status が dropped の受講登録。受講登録の履歴には残りますが、以下のほかのすべての数値からは除外されます |
| **Active learner** | 項目を完了した（課題の提出を含む）、クイズの受験を提出した、または動画内の質問に回答した、受講登録中の受講生。サインインやページを開くことは、どちらも記録されないため数えません |
| **Active this week** | 現在の暦週（月曜から日曜、UTC）におけるアクティブな受講生の延べ人数ではなく重複を除いた人数。分析ページには、直近30日または90日について、UTC の日ごとの重複を除いたアクティブな受講生数も表示されます |
| **Completion rate** | 完了した受講登録を、退会していないすべての受講登録で割った値。そのような受講登録がないコースでは、0% ではなく「No data」と表示されます |
| **Activated** | コース内で最初の行動をした受講登録。受講登録に最終アクティビティ時刻があることを指し、最初に完了した項目、クイズの受験、課題の提出、動画内の質問への回答のいずれかで設定されます。終了した受講登録を含め、すべての受講登録が対象です。受講登録の最終アクティビティ時刻から数えるため、新しいマーカーは保持されず、「現時点まで」の値です。まだ始めていない受講生も、今後アクティベートされる可能性があります。履歴チャートでは、受講生が登録した UTC の日に計上されます |
| **Activation rate** | アクティベートされた受講登録を、すべての受講登録で割った値（どちらも終了したものを含む）。全期間と、直近30日または90日に登録した受講生について表示されます。受講登録のないコースでは、0% ではなく「No data」と表示されます |
| **Prompt answers and dismissals** | 最初のレッスンのプロンプトに回答した受講生の数と、**Not now** を押した受講生の数。受講生はコースごとに1回だけ数えます。プロンプトが表示された回数は記録されないため、率は出しません |
| **Drop-off** | 現在受講生に表示されている各レッスンについて、コースの順に、開始した受講生の数、完了した受講生の数、開始した受講生のうち完了した割合。非表示またはアーカイブされたレッスンと、非表示またはアーカイブされたモジュールのレッスンは含まれません |
| **Score bands** | クイズごとの各受講生の最高スコアを10点刻みの区分（0-9、10-19、... 90-100）にしたもの。受験回数に関係なく、受講生は1回だけ数えます |
| **Most-missed questions** | すべての受験を通じた不正解率の順。順位付けには少なくとも5回の受験が必要なので、1回の悪い受験で1位になることはありません |
| **Video question results** | 受講生に表示され、質問を持つ動画ごと、現在の質問ごとに、その位置（または「End of video」）、プロンプトの冒頭、回答した受講生の数、不正解の数、不正解率を表示します。クイズの質問と同じ、最低5回答の条件で順位付けされます。各受講生の最初に記録された回答だけが対象で、**Try again** とスキップは記録されません。削除された質問は一覧に出ません。結果には受講生の識別子は含まれません |
| **Modules without questions** | レッスン離脱ビューには、受講生に表示される動画があり、表示されるクイズも、質問付きで表示される動画もない、受講生に表示されるモジュールの名前も表示され、講師に質問の追加を促します。現在のカリキュラムから読み取るため、集計値ではなく、ずれることもありません |

## 鮮度

数値は、コースの進捗と同様に、レコードより数秒遅れます。変更（受講登録、完了、クイズの受験）は、通常30秒以内の次の読み込みで反映されます。カードと分析ページのどちらにも、数値が最後に更新された時刻が表示されます。

## 数値の保持方法

`analytics-update` ハンドラーは<Link path="design/stream-event-router">ストリームイベントルーター</Link>の機能です。core テーブルの5つのレコード、`courseStats`、`periodStats`、`lessonStats`、`quizScoreStats`、`quizQuestionStats` にカウンターを保持します。

- **各変更は1回だけ数えられます。** 変更のカウントは、ストリームレコードにちなんだ名前の `analyticsMarker` と一緒に、1つのトランザクションで書き込まれます。再配信されたレコードはマーカーを見つけて、何も数えません。
- **各受講生は、日ごと、週ごとに1回だけ数えられます。** 受講生と期間ごとの2つ目のマーカーにより、「アクティブ」は重複のない受講生の数になります。
- **順序は関係ありません。** カウンターは加算されるだけで、レッスンの離脱の数値は、届いた変更ではなく受講生の現在のレコードから確定されます。

数値がレコードとずれた場合は、`analytics-matches-records` 不変条件が検出し、`pnpm nx run @discava/tooling-deploy:rebuild-analytics -- <courseId>` でコースの数値をレコードから再計算できます。
