講師は、コースを公開した後も編集を続けます。この設計は、それらの編集を、すでに受講登録している受講者にとって安全なものにします。作りかけのものが見えるようになることはなく、受講者が行ったことが失われることもなく、進捗は正しいままです。

編集がどう動くかは、コースのステータスで決まります。

| コースのステータス | 編集 |
|---|---|
| **Draft** | すぐに適用され、削除は完全削除になる。下書きは受講者に公開されたことがないので、そこにあるものが受講者に影響することはない |
| **Published** | このページのルールに従う。受講者には進捗や受験記録がありうる |
| **Archived** | カリキュラムは読み取り専用([コースのライフサイクル](#コースのライフサイクル)を参照) |

プロシージャは instructor-api にあります(`procedures/course.ts`、`module.ts`、`lesson.ts`、そして `content-item-*.ts` の各ファイル)。

## ワークフロー

### コースのライフサイクル

```d2 title="Lifecycle of a course: a draft is published once it has content; archiving makes it read-only and keeps whether it was ever published, and restore returns it there"
direction: right

new: "Created" {shape: oval}
draft: Draft
published: Published
archived_draft: "Archived, read-only\n(never published)" {style.stroke-dash: 3}
archived_published: "Archived, read-only\n(was published)" {style.stroke-dash: 3}

new -> draft
draft -> published: "publish\n(needs visible content)"
draft -> archived_draft: archive
published -> archived_published: archive
archived_draft -> draft: restore
archived_published -> published: restore
```

**公開**

- 公開できるのは **draft** だけで、しかも受講者に見えるコンテンツアイテムが少なくとも1つある場合に限られます。そのため、コースが空のまま公開されることはありません。非表示またはアーカイブされたコンテンツアイテム、および非表示またはアーカイブされたモジュールやレッスンの下にあるものは数えません。
- アーカイブされたコースの公開は拒否されます。先に復元してください。
- コースを公開しても、その下のどのレコードも変更されません。下書きで `visible` のレコードはコースと同時に受講者に見えるようになり、非表示のものは公開されるまで非表示のままです。

**復元**

- コースは最初に公開されたときに `publishedAt` を記録し、決して消去しません。これによって、アーカイブされたコースが、受講者に公開されたことがあるかを記憶しています。
- **復元すると、公開されていたコースは Published に、一度も公開されていないコースは Draft に戻ります。** 受講者が利用したコースが、削除が完全削除になる draft に戻ることはありません。

**アーカイブされたコースは読み取り専用**

- カリキュラムのどれも、追加、編集、公開、非表示、アーカイブ、並べ替え、復元ができず、動画もアップロードできません。これらはいずれも `PRECONDITION_FAILED`("Restore the course first")を返します。モジュール、レッスン、コンテンツアイテム、クイズのすべてが対象です。
- できることは、コースの閲覧、復元、そして**すでにアーカイブされているレコードの完全削除**です。これにより、アーカイブされたコースを、復元して再び受講者に見せることなく整理できます。これらの削除には独自のガードがあります([完全削除](#完全削除)を参照)。
- コース自体の設定(価格、修了証のスイッチと基準、最初のレッスンのプロンプト)は、どのステータスでも変更できます。

**繰り返しと競合**

- 操作を繰り返しても何も書き込まれません。公開済みのコースを公開する、またはアーカイブされていないコースを復元すると、コースはそのまま返されます。タイムアウト後の再試行は安全です。
- 各変更は、読み取ったステータスを条件にします。その間にコースが変わっていれば、リクエストは `CONFLICT` を返します。
- **同時に行われる編集に対する公開。** draft のコースでは、コンテンツはいつでも削除、非表示、アーカイブされうる状態です。そのため公開のトランザクションは、数えた表示状態のコンテンツアイテムの1つと、その下にあるレッスンとモジュールが、まだ存在し、まだ表示されていることを確認します。そうでなければ何も公開されず、リクエストは `CONFLICT` を返します。再試行すれば、数え直されます。
- **同時に行われる公開に対する削除。** 削除が完全削除かアーカイブかは、リクエストが読み取ったときのコースのステータスで決まります。そのため、draft のコースでの完全削除(モジュール、レッスン、コンテンツアイテムの)は、コースがまだ draft であることも確認するトランザクションで実行されます。その間に公開されていれば、何も削除されず、リクエストは `CONFLICT` を返します。再試行すれば、代わりにアーカイブされます。
- **同時に行われるアーカイブに対するあらゆる書き込み。** コースがアーカイブされていないことの確認は、モジュールとレッスンの確認と並んで、各書き込みと同じトランザクションの一部です。その競合に負けたリクエストは "Restore the course first" を返します。

### モジュール、レッスン、コンテンツアイテムのライフサイクル

```d2 title="Lifecycle of a module, lesson or content item: the course's status decides where a new record starts and what delete does; then publish, hide, archive, restore and delete"
direction: down

new_draft: "Created in a\nDraft course" {shape: oval}
new_live: "Created in a\nPublished course" {shape: oval}

live: "Not archived" {
  visible: Visible
  hidden: Hidden

  hidden -> visible: publish
  visible -> hidden: hide
}

archived: "Archived\n(frozen until restored,\nwith everything under it)" {
  style.stroke-dash: 3
}

deleted: Deleted permanently {shape: oval}

new_draft -> live.visible
new_live -> live.hidden
live -> archived: "delete\n(course not Draft)"
archived -> live: restore
live -> deleted: "delete\n(course Draft)"
archived -> deleted: "delete permanently\n(see below)"
```

- この図は、1つのモジュール、レッスン、またはコンテンツアイテムを追っています。コース自体のステータスは別のもので(上記を参照)、これらの操作のどれもそれを変えません。コースのステータスは、新しいレコードがどこから始まるか、そして削除がレコードをアーカイブするか取り除くかを決めます。アーカイブされたコースでは、アーカイブされたレコードの完全削除を除き、これらの操作はどれも許可されません。
- 受講者にレコードが見えるのは、それが **Visible** で、すべての祖先もそうである間だけです([実効的な表示](#実効的な表示)を参照)。
- モジュールやレッスンを公開すると、その下にある、一度も公開されていない、非表示でアーカイブされていないレコードもすべて公開されます。表示されていた後に意図的に非表示にされたレコードは、非表示のままです。非表示、アーカイブ、復元は、そのレコード自体だけを変更します。
- アーカイブされたレコードは表示設定を保持するため、復元すると、元のとおり **Visible** か **Hidden** で戻ります。復元できるのは、親のモジュールやレッスンがアーカイブされていない場合に限ります。
- アーカイブされたレコードとその下のすべては凍結されます。その中のものは公開、非表示、編集ができず、何も追加できません。
- draft のコース以外では、受講者に見えるものへのあらゆる変更が、受講登録しているすべての人の進捗の再計算を引き起こします。

## データモデル

ライブ編集を支える `curriculum` エンティティの属性です。

| 属性 | 対象 | 目的 |
|---|---|---|
| `visibility: 'hidden' \| 'visible'` | モジュール、レッスン、コンテンツアイテム | 必須。作成のプロシージャは、draft のコースでは `visible`、公開済みのコースでは `hidden` に設定するため、新しいクイズ、レッスン、モジュールが作りかけのまま見られることはない。講師が **Publish** をクリックして表示する |
| `archivedAt` | モジュール、レッスン、コンテンツアイテム | ソフトデリート。アーカイブされたレコード自体にだけ設定される。その子が非表示になるのは、親がアーカイブされているからで、子自身がアーカイブされているからではない |
| `publishedAt` | モジュール、レッスン、コンテンツアイテム | レコードが最初に表示された時点。draft のコースでの作成時、または最初の公開時。消去されることはない([公開する](#公開する)を参照) |
| `studentActivityCount` | コンテンツアイテム | そのアイテムについて何らかのデータを持つ、異なる受講者の数。減らされることはない |
| `lastChildOrder` | コース、モジュール、レッスン | 子に最後に割り当てられた `order`。子を追加または復元すると、同じトランザクションで次の値を確保するため、同時に追加された2つのレコードが `order` を共有することはない |

**何が受講者のアクティビティとして数えられるか。** `studentActivityCount` は、受講者のそのアイテムに対する**最初の**レコードを作成するのと同じトランザクションで加算されます(`ADD 1`)。

| アイテム | 最初のレコード |
|---|---|
| クイズ | `quizSummary` |
| 動画 | `itemCompletion` または `videoAnswerSheet` のうち先に作られたほう。動画の問題への回答は、完了と同様に受講者を数える |
| アップロード課題 | `assignmentSubmission` または `itemCompletion` |
| テキスト、ファイル | `itemCompletion` |

すべての書き込み元は `studentActivityWrites`(`core-table/src/helpers/student-activity.ts`)からトランザクションを組み立て、`helpers/invariants/student-activity.ts` の不変条件が、その数をレコードと照らして確認します。

`studentActivityCount` はカリキュラムのパーティションにあるため、モジュールやレッスンの下にあるすべてについて合計したり確認したりするのは、1回のクエリで済みます。それが数える受講者側のレコードはユーザーをキーとしており、スキャンなしには「誰がこのアイテムを使ったか」に答えられません。

## 実効的な表示

レコードが受講者に表示されるのは、そのレコードとすべての祖先が `visible` でアーカイブされていない場合だけです。これは次の箇所で確認されます。

- 受講者向けのすべての読み取り: core-api の `course.view` と `course.publicView`、そして `quiz.view`
- 受講者向けのすべての書き込み: クイズの提出、アイテムの完了の記録
- すべての進捗計算

そのため、モジュールを非表示またはアーカイブすると、その中のクイズも提出できなくなり、そのアイテムはすべての人の進捗から取り除かれます。

このルールは `core-table/src/helpers/curriculum.ts` に1回だけ実装されています。1つのレコード向けの `isShown` と、カリキュラム全体向けの `filterEffectivelyVisible` です。core-api のコースビューがこれを使い、`packages/events` の再計算 Lambda が実行する core-table の進捗計算も同じです。受講者に見えるものと、その進捗が数えるものが食い違うことはありません。

講師は、instructor-api の `course.view` を通じて編集します。これは、非表示とアーカイブされたレコードも、その `visibility`、`archivedAt`、`studentActivityCount` とともに含むカリキュラム全体を返します。コースを教える講師に限られます。コースエディターは、アーカイブされたレコードをメインの一覧から除き、非表示のものには **Hidden** と表示します。

## 公開済みコースでの操作

| 操作 | 受講者に見えるもの | 受講者のデータと進捗 | 進捗が再計算される対象 |
|---|---|---|---|
| **Add module** | 公開されるまでは何も見えない。公開すると非表示のレッスンとアイテムも公開されるため、すべて一度に現れる | 公開されると、全員の `progressPercent` が下がる。完了したレッスンとコースは完了のまま | 公開時に、受講登録しているすべての受講者 |
| **Remove module** | アーカイブされる。次回の読み込みでアウトラインから消える。そのページにいる受講者には "This lesson has been removed by your instructor" と表示される | 保持される(完了、受験、最高スコア)が、もう数えられない。ほかのすべてを終えていた受講者は `completed` になる。復元でき、復元すればすべてが再び数えられる | 受講登録しているすべての受講者 |
| **Edit module**(タイトル、説明) | すぐに適用される | 影響なし | 誰も対象にならない |
| **Add lesson** | 公開されるまでは何も見えない(非表示のアイテムと一緒に公開される) | モジュールの追加と同じ | 公開時に、受講登録しているすべての受講者 |
| **Remove lesson** | モジュールの削除と同じ | モジュールの削除と同じ | 受講登録しているすべての受講者 |
| **Edit lesson**(タイトル、説明) | すぐに適用される | 影響なし | 誰も対象にならない |
| **Add content item** | 公開されるまでは何も見えず、そのレッスンとモジュールも公開されている場合に限る | 公開されると `progressPercent` が下がる。そのレッスンがすでに完了していた場合、レッスンは完了のままで、アイテムは **New** と表示される | 公開時に、受講登録しているすべての受講者 |
| **Remove content item** | アーカイブされる。次回の読み込みで消える。その中のクイズの提出や完了の記録は "no longer available" で拒否される | 保持されるが数えられない。受講者の唯一の未完了のアイテムだった場合、レッスン(場合によってはコース)が完了になる。復元できる | 受講登録しているすべての受講者 |
| **Edit content item**: タイトル、説明、テキスト本文 | すぐに適用される | 完了は保持される | 誰も対象にならない |
| **Edit content item**: 動画の差し替え | 動画の差し替えと再トランスコードのフローを通る。新しいバージョンの準備ができるまで、受講者は前のバージョンを再生し続け、トランスコードが失敗しても同様。前のバージョンのファイルは、新しいバージョンが、閲覧者の署名付き Cookie の有効期間より長く準備完了の状態になってから削除される | 完了は保持される | 誰も対象にならない |
| **Edit content item**: 動画内の問題 | <Link path="design/quizzes">クイズ</Link>を参照。キーや解説だけの変更は見えない。問題文、種類、オプションの変更は、回答中の提出に `CONFLICT` を返させ、何も記録しない。問題の移動や削除は、記録済みの回答に触れない | 完了と進捗は影響を受けない。記録済みの回答は保持され、再採点されない | 誰も対象にならない |
| **Edit content item**: クイズ | <Link path="design/quizzes">クイズ</Link>を参照。回答キーだけの編集は見えない。問題の編集は、受験中の提出に `CONFLICT` を返させる | 受験、最高スコア、合格は保持され、再採点されない | 誰も対象にならない |
| **Hide**(どの階層でも) | 削除のように消えるが、Archived ビューには表示されない | 保持されるが数えられない。再び表示されれば、また数えられる | 受講登録しているすべての受講者 |
| **Reorder**(どの階層でも) | すぐに適用される | 影響なし | 誰も対象にならない |

「進捗の再計算」は、<Link path="design/progress-and-completion">進捗と完了</Link>で説明されているサーバー側の Lambda が行い、受講者のブラウザが行うことは決してありません。

## 公開する

モジュールやレッスンを公開すると、それと、その**新しい**非表示の子孫のすべてが、**1つのトランザクション**で `visible` に設定されます。受講者は、新しいレッスンがすべてのアイテムとともに一度に現れるのを目にし、少しずつ現れることはありません。

どの子孫が親と一緒に公開されるか:

| 子孫 | 親と一緒に公開されるか |
|---|---|
| 非表示で `publishedAt` がない(新しいコンテンツ) | はい |
| 非表示で `publishedAt` がある(受講者に見えた後、意図的に非表示にされた) | いいえ。非表示のまま |
| アーカイブされている、またはアーカイブされたレッスンの下のコンテンツアイテム | いいえ。そのまま |

- 自分で公開するレコードは、履歴にかかわらず常に公開されます。
- すべてのモジュール、レッスン、コンテンツアイテムは、最初に表示されたとき(draft のコースで作成されたとき、または最初に公開されたとき)に `publishedAt` を記録し、決して消去しません。
- これで区別できない唯一のケースは、一度も公開される前に非表示にされたレコードです(たとえば、公開済みのコースで新しいレッスンを作っている最中に、そのアイテムを非表示にした場合)。これも新しいものとして数えられ、親と一緒に公開されます。
- **公開の最中にアーカイブされた場合。** 公開が変更するすべてのレッスンとアイテム(および公開するすべてのアイテムのレッスン)は、トランザクションがコミットされるときにまだアーカイブされていない必要があります。そうでなければ何も公開されず、リクエストは `CONFLICT` を返します。再試行すると、モジュールやレッスンが読み直され、新たにアーカイブされたレコードはスキップされます。

非表示はカスケードされません。そのレコード自体だけを変更し、その子は自身の `visibility` を保ちます。レコードは表示されている祖先の下でしか表示されないため、受講者はいずれにせよ子が見えなくなります。

## 並べ替え

モジュールはコース内で、レッスンはモジュール内で、コンテンツアイテムはレッスン内で、それぞれ `order` で並べ替えられます。各階層に変更方法は1つずつあり、`module.reorder`、`lesson.reorder`、`contentItem.reorder` です。`module.update` と `lesson.update` は `order` を受け取りません。

- 講師ポータルでは、各行のグリップがドラッグハンドルです(マウス、タッチ、キーボード)。アーカイブされたコース、または並べ替えるレコードが1つしかない場所には、ハンドルはありません。
- 並べ替えは他の編集と同じ編集なので、アーカイブのルールに従います。アーカイブされたコース、およびアーカイブされたモジュールやレッスンの下では拒否されます("Restore the course (module, lesson) first")。
- すべてのコンテンツアイテムの種類に同じように適用されます。
- レッスンを別のモジュールへ、コンテンツアイテムを別のレッスンへ移動することはサポートされていません。そのキーに親の ID が含まれているからです。

各プロシージャは、親の中で**アーカイブされていないすべてのレコード**の ID を、表示したい順に受け取り、すべての `order`(1, 2, 3, ...)を1つのトランザクションで書き込むため、1回のドラッグが1つのアトミックな変更になります。

- リストは親と完全に一致している必要があります。レコードが欠けている、アーカイブまたは削除されたものが含まれている、または不明な ID が含まれている場合、リクエストは `CONFLICT` を返し、何も書き込みません。エディターが古いリストで作業していたことになるので、再読み込みしてやり直します。同じ ID が2回現れると `BAD_REQUEST` です。
- 各レコードは、祖先の確認と同じトランザクションの中で、まだアーカイブされていないことを条件とします。そのため、リクエストの実行中にアーカイブされたレコードや、その瞬間にアーカイブされた祖先があれば、並べ替え全体が取り消されます。
- アーカイブされたレコードはリストに含まれません。それらは元の `order` を保持します。
- 親がすでに持っている順序を繰り返しても、何も書き込まれません。
- トランザクションが保持できるのは、祖先の確認を含めて最大100レコードなので、上限は次のとおりです。

  | プロシージャ | 確認 | 最大レコード数 |
  |---|---|---|
  | `module.reorder` | course | コース内のモジュール99個 |
  | `lesson.reorder` | course, module | モジュール内のレッスン98個 |
  | `contentItem.reorder` | course, module, lesson | レッスン内のコンテンツアイテム97個 |

  これより大きな親は、他の親全体を対象とするオペレーションと同様に、`PRECONDITION_FAILED` で拒否されます。
- 並べ替えと同時に追加されたレコードは、並べ替えられたものの後ろに置かれ、エディターが再読み込みすると表示されます。
- 復元されたレコードは親の末尾に置かれる([復元する](#復元する)を参照)ため、他のレコードと `order` を共有することはありません。

## 削除(アーカイブ)

draft のコース以外では、削除は常にアーカイブになり、講師ポータルはその操作を **Archive** と表示します(draft のコースでは、モジュールとレッスンは **Delete**、コンテンツアイテムは **Remove** です)。確認ダイアログには、`studentActivityCount` から影響が表示されます。

- コンテンツアイテム: 何人の受講者が使ったか。たとえば "12 students have used it"。
- モジュールまたはレッスン: その下のアイテムのうち、受講者が使ったものの数。たとえば "Students have used 3 items in it"。アイテムをまたいで受講者を合計すると、使ったアイテムごとに1回ずつ受講者を数えることになるため、数えるのは受講者ではなくアイテムです。

いずれの場合も、受講者の進捗は保持され、レコードが復元されれば再び数えられるという説明が加わります。

### 受講者が学習している最中に削除された場合

| 受講者のいる場所 | 何が起きるか |
|---|---|
| コース内の別の場所 | 次回読み込んだときに、モジュールやレッスンがアウトラインから消える |
| そのレッスンのページ | すでに画面にあるコンテンツは読めたまま。次のデータ再取得(ナビゲーション、ウィンドウフォーカス)で、アウトラインに戻るリンク付きで **"This lesson has been removed by your instructor"** と表示され、素の 404 になることはない |
| その中のクイズの途中 | 提出は拒否され("This quiz is no longer available")、ローカルの下書きは破棄され、受験回数は消費されない |
| アイテムの完了の記録 | 同じように拒否される |
| 古いリンクやブックマーク | 同じ「削除済み」ページ |

アーカイブは、受講登録しているすべての受講者の進捗の再計算を引き起こすため、削除されたコンテンツは、誰も再読み込みしなくてもすぐに数えられなくなります。

### アーカイブされたレコードに対してできないこと

アーカイブされたレコードとその下のすべては、復元されるまで、アーカイブされたときのままに保たれるため、復元すれば受講者が見ていたものが戻ります。アーカイブされた**コース**も同じように凍結され([コースのライフサイクル](#コースのライフサイクル)を参照)、アーカイブされているときは、まずコースが名指しされます。"Restore the course first"。次のものはすべて `PRECONDITION_FAILED` で拒否されます。

- アーカイブされたレコード自体の公開、非表示、編集: "Restore the module (lesson, content item) before publishing (hiding, editing) it"。
- その下にあるものの公開、非表示、編集。たとえば、アーカイブされたモジュール内のレッスンや、アーカイブされたレッスン内のコンテンツアイテム: "Restore the module first" または "Restore the lesson first"。両方がアーカイブされている場合は、モジュールが先に名指しされます。
- その下への追加: アーカイブされたモジュールに新しいレッスンは追加できず、アーカイブされたモジュールやレッスンに新しいコンテンツは追加できません。
- 動画ファイルのアップロード: アーカイブされたコース、モジュール、レッスンには、またはアーカイブされたコンテンツアイテムのファイルを差し替えるためのアップロード URL は発行されません。

アーカイブされたモジュールやレッスンの下にあるレコードは、コースがアーカイブされていない限り、自らをアーカイブし、その後に完全削除することができます。

これらのルールは、リクエストが重なっても守られます。モジュールやレッスンの下へのすべての書き込みは、そのコース、モジュール(とレッスン)がまだ存在してアーカイブされていないこと、そしてレコード自体がアーカイブされていないことの確認とともに、1つの DynamoDB トランザクションで実行されます。その間に別のリクエストが親をアーカイブまたは削除すれば、書き込み全体が同じエラーで拒否され、何も書き込まれません。そのため、アーカイブ中または完全削除中のモジュールに、土壇場で新しいレッスンが加わったり、レッスンに新しいアイテムが加わったりすることはありません。

まだトランスコード中にアーカイブされた動画は、トランスコードを続けます。ジョブが終了すると、アイテムは `archivedAt` や `visibility` に触れずに `ready`(または `failed`)とマークされるため、復元されれば再生され、それまでは非表示のままです。

## 復元する

講師のコースページには **Archived** セクションがあり、それ自体でアーカイブされたすべてのレコードを、新しいものから順に一覧します。アーカイブされたモジュール、アクティブなモジュール内でアーカイブされたレッスン、アクティブなレッスン内でアーカイブされたアイテムです。アーカイブされた親の下にあるレコードは、親と一緒に戻るため、個別には一覧されません。各行には、レコードがあった場所、アーカイブされた日時、その中身、受講者が使ったかどうかが表示され、**Restore** と **Delete permanently** があります。

- 復元すると `archivedAt` が消去され、レコードは親の**末尾**に置かれます(`writeAtEnd`)。その `order` は、アーカイブされたものを含むすべての兄弟のうち最大のものより1つ大きく、親の `lastChildOrder` よりも大きくなります。そのため最後に並び、後から復元される別のアーカイブ済みレコードと衝突することもありません。講師が好きな位置にドラッグします。
- アーカイブされる前の位置は保持されません。その後に他のレコードが並べ替えられている可能性があり、その位置がすでに使われているかもしれないからです。
- レッスンを復元できるのは、そのモジュールがアーカイブされていない場合だけで、コンテンツアイテムを復元できるのは、そのモジュールもレッスンもアーカイブされていない場合だけです。そうでなければ "Restore the module first" または "Restore the lesson first" で拒否され、両方がアーカイブされている場合はモジュールが先に名指しされます。
- コース自体がアーカイブされている間は、何も復元できません。"Restore the course first" で拒否されます。
- 復元されたクイズは、バージョン、受験、最高スコアを保持します。
- 復元は進捗の再計算を引き起こし、すべてが以前のとおり再び数えられます。

## 完全削除

Archived ビューからのみ提供され、次のすべてが成り立つ場合に限られます。

- レコード自体がアーカイブされている(アーカイブされた親の下にあるものは、先にアーカイブする必要がある)
- アイテム、またはレッスンやモジュールの下のすべてのアイテムについて、`studentActivityCount` が 0 である
- レッスンやモジュールの場合、そのレッスン、またはモジュールのどのレッスンにも、ディスカッションの質問が投稿されていない。質問も受講者のデータだからです

受講者が使ったものは、アーカイブはできますが、完全削除は決してできません。エディターは、それに対して **Delete permanently** を、その理由とともに利用不可として表示します。アーカイブされたコースでも動作します。そのコースが許可する唯一のカリキュラム編集です。

確認と削除は別の呼び出しなので、削除自体にも条件があります。

- **モジュールまたはレッスン**は、その下のすべてとともに1つのトランザクションで削除されます。各コンテンツアイテムの削除は、確認した `updatedAt`(どの書き込みでも更新される)と `studentActivityCount = 0` を条件にします。モジュールまたはレッスン自体の削除は、確認した `archivedAt` を条件にするため、その間に復元が入れば取り消されます。モジュールの下のレッスンは、それ自体の条件なしで削除されます。
- **単一のコンテンツアイテム**は、`studentActivityCount = 0` で、かつアイテムがまだアーカイブされていることを条件とする、1回の削除です。

条件が満たされない場合、削除は `CONFLICT` で拒否され、何も取り除かれません。トランザクションのその他の失敗は `INTERNAL_SERVER_ERROR` として報告され、やはり何も取り除かれません。

削除後、動画の実行中のトランスコードはキャンセルされ、動画とファイルの S3 オブジェクトが取り除かれます。この後片付けはベストエフォートで、失敗はログに記録されるだけで、例外にはなりません。

## 上限と繰り返しのリクエスト

- **全体のセットのみ。** モジュールやレッスンの公開と、その削除(draft のコースまたは完全削除)は、最初の 1 MB だけでなく、子孫のすべてのページを読み取るため、公開されないまま、あるいは孤立したまま残るものはありません。2つの `course.view` も、カリキュラムのすべてのページを読み取ります。
- **100アイテムのトランザクション。** モジュールやレッスンの公開と、その削除(draft のコースまたは完全削除)は、すべてか無かの1つの DynamoDB トランザクションで行われ、これは最大100レコードまでです。コース(と、レッスンを公開する場合はモジュール)の確認も、その上限に含まれます。より大きなモジュールやレッスンも、段階的になら公開または削除できます。
  - 先にそのレッスン(またはコンテンツアイテム)の一部を公開し、それからモジュール(またはレッスン)を公開する
  - draft のコースでは、先にそのレッスン(またはコンテンツアイテム)の一部を削除し、それからモジュール(またはレッスン)を削除する
  - それ以外では、先にそのレッスン(またはコンテンツアイテム)の一部をアーカイブして完全削除し、それからモジュール(またはレッスン)を削除する

  オペレーションが上限を超える場合、`PRECONDITION_FAILED` で拒否され、次の手順を示すメッセージが表示されます。裏で複数のトランザクションに分割されることは決してありません。その1つが失敗すると、モジュールの一部がすでになくなり、親のないレッスンやアイテムが残ってしまうからです。
- **繰り返しは何も書き込まない。** すでにアーカイブされたものをアーカイブしても、元の `archivedAt` が保たれます。すでに表示されているコンテンツアイテム、または中にも下にも非表示のものがないモジュールやレッスンを公開する、非表示のものを非表示にする、アーカイブされていないものを復元する、といった操作は、いずれもレコードを変更せずに返します。たとえばクライアント側のタイムアウト後の再試行のようなリクエストの繰り返しは、害がありません。例外は、レコードを取り除く削除(draft のコース、または完全削除)です。再試行すると、レコードはすでになくなっているため `NOT_FOUND` が返ります。
