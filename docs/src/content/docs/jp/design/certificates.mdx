## ルール

**修了証は、進捗の再計算によってサーバー側でのみ書き込まれ、受講生1人につきコースごとに最大1枚です。** 受講生がコースを修了し（<Link path="design/progress-and-completion">進捗と完了</Link>を参照）、**かつ**その時点でコースに適用されている基準を満たしたときに発行されます。受講生や講師がブラウザで行う操作によって修了証が作られることはありません。

修了そのものは基準の影響を受けません。表示されているすべての項目が完了すると、受講登録は引き続き `completed` になります。「修了したが、まだ修了証がない」状態は通常の状態で、長く続くこともあり、コースホームには、まだ必要なことが表示されます。

## 基準

- **保存場所**: コースの `certificateCriteria` マップで、コースごとのスイッチの隣にあります。`{ version, requireQuizPass }` の形です。新しいコースは `{ version: 1, requireQuizPass: false }` です。作成後にこれを書き込むのは `setCertificateCriteria` だけで、何かが変わったときにだけ `version` に1を加えます。
- **ルール**: `core-table` の `evaluateCertificateCriteria` は純粋関数で、発行側と読み取り側（コースホームが表示する `certificate.requirements`）の両方が使うため、ページと発行側が食い違うことはありません。`requireQuizPass` がオンの場合、評価対象のすべてのクイズに合格している必要があります。つまり `passedAt` が設定されていて（`passedAt` は永続的です）、**かつ**受講生の最高スコアがそのクイズの*現在の*合格点に達していることです。そのため、合格点を上げると、まだ発行されていない修了証が保留になることがあり、下げると発行されることがあります。評価対象のクイズとは、有効に表示されていて合格点が0より大きいクイズのことです。合格点が0%のクイズは練習用で、評価対象ではありません。
- **公開中のコースで基準を変更する**: 受講生が評価される時点で読み取られた基準が適用されます。すでに発行された修了証が再審査されることはありません。基準を緩めると、新たに条件を満たすすべての人に修了証が発行され、厳しくすると、まだ条件を満たしていない受講生にだけ影響します。講師向けのコントロールには、保存の前にこのことが表示されます。

## 採点されるアップロード

2つ目の基準 `minUploadScorePercent`（1〜100の整数。不要なときは存在しない）は同じマップにあり、同じ `setCertificateCriteria` で設定します。`null` を渡すと削除されます。

- **ルール**: これが設定されている場合、有効に表示されているすべての課題が評価対象になります。受講生の提出物が `returned` で、`floor(points / pointsOutOf * 100)` が最小値以上のとき、その課題は達成です。`pointsOutOf` は、その提出物が何点満点で採点されたかを表します（読み取れる採点がない場合は課題の `maxPoints`）。提出物がない場合は「not submitted」、まだ返却されていない場合は「waiting to be graded」、返却されたがポイントが足りない場合は「below the score」です。表示されている課題がないコースには、達成すべきものがありません。
- **再採点**: 提出物の `status`、`points`、`returnedAt` のいずれかが変わると、その受講生が再計算されます。そのため、成績が上方に修正されれば修了証が発行され、再提出（これらのどれも変えない）では何も起きません。
- **記録される内容**: 修了証の `assessment` は、`minUploadScorePercent`、`assessedUploadCount`、そして内部リストに課題ごとに1件の `upload` エントリを保持します。スコア区分はクイズとアップロードを合わせたものです。ステートメントには「Graded assignments returned with at least 60%: 2.」という行が加わります。
- 提出物は、この基準が設定されている場合にだけ読み取られます。

## 修了証が記録する内容

修了証は、発行時の基準を `version` とともに読み取り専用の `assessment` にコピーします。そのため、コースが変更されても、修了証が説明する内容がずれることはありません。

- 2つの設定、表示されている項目の数、評価対象の項目の数、最低と最高の合格点、コースの長さ（時間）、そして**スコア区分**（最高スコアの平均を10点刻みにした区分で、0〜9%から90〜100%まで）。それぞれが、公開ページと PDF に同じ文面（`assessmentStatement`）として表示されます。
- 各スコアを含む**評価対象項目のリスト**。不変条件がルールを検証できるようにするためのもので、どの API からも返されず、表示もされません。
- 何も必須でなかった場合は、区分はなく、ステートメントには「No graded assessment was required for this certificate.」と表示されます。正確なスコアが表示されることはありません。

## 保留中の修了証が届くきっかけ

再計算（<Link path="design/progress-and-completion">進捗と完了</Link>を参照）は、項目の完了以外でも実行されます。条件を満たした受講生には、次のきっかけから数秒以内に修了証が発行されます。

- 項目がすでに完了していたクイズに合格した場合（受験回数を使い切った、上限が引き上げられた、後の受験で合格した）、またはすでに合格したクイズでより良い最高スコアが出た場合: その受講生
- 基準が変更された、または修了証がオンになった場合: 退会していない受講登録中のすべての受講生
- クイズの合格点が変更された場合（0への変更、0からの変更を含み、評価対象かどうかが変わります）: 退会していない受講登録中のすべての受講生
- すでにきっかけになっていた、項目の完了と可視性の変更

そのため、修了証をオンにしたり基準を緩めたりすると、すでに条件を満たしているすべての人に発行されます。

## 発行の仕組み

- 進捗再計算の Lambda は、受講生の進捗と受講登録を書き込んだ後、受講生が退会しておらず、受講登録が `completed` の場合に `issueCertificate` を呼び出します。
- まず、そのコースにおける受講生の `certificate` を読みます。ない場合にだけ、コースとユーザーを読むので、学習途中の受講生や、すでに修了証を持つ受講生には、余分な読み取りが発生しません。
- `certificate` を書き込むのは `issueCertificate` だけです。キーがまだ存在しないことを条件にレコードを作成するため、2つの再計算が同時に動いても、修了証は1つの ID で1枚だけ残り、どちらもそれを返します。エラーが握りつぶされることはなく、バッチは再試行されます。
- 修了証は、印刷される内容（受講生の名前、コースのタイトル、修了日）を発行時にコピーします。後でコース名を変更しても、修了証は変わりません。
- ID は Crockford base32 の16文字で、`XXXX-XXXX-XXXX-XXXX` の形で表示されます。検索ではダッシュ、スペース、大文字小文字が無視され、`O` は `0`、`I` と `L` は `1` として読まれます。

## コースごとのスイッチ

講師は、コースの設定で **Issue a certificate on completion** をオンまたはオフにできます。コースの status は問いません。新しいコースではすべてオンです。

- 切り替えた時点から適用されます。オフにしても、すでに発行された修了証が削除されたり無効になったりすることはなく、オンにすると、すでに条件を満たしているすべての受講生に数秒以内に修了証が発行されます。
- スイッチがオフの間も、既存の修了証は引き続き検証できます。

## 公開ページに表示される内容

受講生ポータルの `/certificates/<ID>` はサインイン不要です。表示されるのは、受講生の名前、コースのタイトル、修了日、修了証 ID、評価のステートメントだけで、それ以外は表示されません。メールアドレス、ユーザー ID、項目ごとのスコア、受講生のアカウントへのリンクはありません。形式が不正な ID や不明な ID には、同じ「Certificate not found」が表示されます。

**取り消された**修了証には、ID と日付とともに「This certificate has been revoked and is no longer valid」と表示され、受講生、コース、理由、操作した人についての情報は表示されません。以前は検証できていた ID がプラットフォームの障害のように見えないよう、「not found」とは区別されています。変更はページの次の読み込みで反映され、リンクプレビューと PDF のチェックも追従します。`certificate.pdf` は取り消された修了証を拒否します（「This certificate has been revoked」）。すでにダウンロードされた PDF は回収できないため、正しい情報はページにあります。

## 取り消しと復元

- **誰が**: コースの講師は、そのコースの修了証を一覧し（コースの Certificates セクション）、理由 `academic-integrity`、`issued-in-error`、`other`（メモ付き）のいずれかで取り消せます。管理者は ID で任意の修了証を検索でき、`refunded` も使えます。
- **プロシージャ**: instructor-api の `certificate.list`、`history`、`revoke`、`restore`、および admin-api の `certificate.get`、`revoke`、`restore`。
- **復元**: 管理者はいつでも復元できます。講師は、講師が行った取り消しだけを復元できます。もう一方の種類の取り消しでは、講師には「Revoked by an administrator」と表示され、Restore は表示されません。
- **レコード**: 修了証は現在の状態（`revokedAt`、`revocationReason`、`revokedByRole`）を持ち、変更のたびに、同じトランザクションで `certificateEvent`（`revoked` または `restored`、操作者、ロール、理由、メモ、時刻）も追記されます。両方を書き込むのは `core-table` の `revokeCertificate` と `restoreCertificate` だけです。履歴は監査のために保持され、取り消し、復元、再度の取り消しを行うと、3件のイベントが残ります。
- **競合**: 書き込みは想定する状態を条件にするため、2つの取り消しが同時に行われても、取り消しとイベントは1件だけ残り、両方のリクエストに応答が返ります。
- **置き換えられない**: 取り消された修了証は ID を保持し、再発行されることはありません。再計算は、既存の修了証があればその status に関係なく止まります。復元すると、同じ ID が再び有効になります。
- **受講生への通知**: 変更の後、理由のカテゴリと、修了証 ID とイベント時刻による重複排除キーを付けて、`certificate.revoked` と `certificate.restored` の通知が送られます。
- **自動で取り消されるものはありません。** 特に返金では取り消されません。修了証は返金後も残り、必要な場合は管理者が理由 `refunded` で取り消します。これはデフォルトで下された判断です（すべての返金で取り消す場合に何が変わるかは、spec の research R-8 に記載されています）。メンテナーの確認待ちです。
- **取り消された修了証はアクションを隠します**: LinkedIn のアクションは非表示になり、`recordLinkedInClick` はそれを拒否し、共有のリマインダーも送られません。

## 不変条件

不変条件のチェック（spec の research R-10 を参照）は、次のことを保証します。修了証の `assessment` が正しい形であり、その件数、合格点、区分が、リストされた項目から導かれること。リストされたすべてのクイズが、発行時刻までに合格点以上で受講生によって合格されていること、リストされたすべてのアップロードが記録された最小値以上のスコアで、提出物がまだ存在していること（`certificate-met-criteria`）。修了証が取り消されているのは、最新のイベントが `revoked` のときだけであること（`certificate-status-matches-history`）。すべてのコースが正しい形の基準を持つこと。そして、取り消されているかどうかにかかわらず、修了証には、修了済み（または修了後に退会）の受講登録が必要であること。さらに、LinkedIn クリックの形、クリック後にリマインダーが送られていないこと、修了証とその通知が一致していることもチェックします。違反にならないもの: 修了証のない修了済みの受講登録、コースの現在の基準とは異なる修了証、その後に非表示になったり合格点が上がったりしたリスト内のクイズ。

## 共有と検証

受講生は、**My Learning** の修了済みの各コースで修了証を見つけます。次の4つのアクションがあります。

- **View** は公開ページを開きます。
- **Download PDF** は、同じ ID とページのアドレスを載せた、A4 1ページの修了証を保存します。
- **Copy link** は公開ページのアドレスをコピーします。
- **Add to LinkedIn profile** は、LinkedIn の新しい認定資格のフォームを開きます（下記を参照）。

リンクまたは ID を持つ人なら誰でも、そのページで修了証を確認できます。

## LinkedIn への追加

受講生ポータルは、受講生のブラウザでリンクを作成して（`lib/linkedin-add-to-profile.ts` の `buildLinkedInAddToProfileUrl`）開きます。サーバーがそれを作成したり見たりすることはなく、受講生がクリックするまで LinkedIn には何も送られません。

- **送られる内容**: LinkedIn の `profile/add` アドレスに、`startTask=CERTIFICATION_NAME`、`name`（修了証に印刷されるコースのタイトル）、発行者（管理ポータルの Branding ページで設定したプラットフォーム名による `organizationName`、またはステージが `linkedInOrganizationId` を設定している場合は代わりに `organizationId`。両方が付くことはありません）、`issueYear` と `issueMonth`（UTC の修了日から）、`certUrl`（公開ページのアドレス）、`certId`（表示されている形）が付きます。有効期限はありません。すべての値はパーセントエンコードされます。
- **送られない内容**: 受講生の名前、メールアドレス、ユーザー ID、セッションの値は一切送られません。LinkedIn はメンバーが誰かを知っているので、こちらからは伝えません。リンクには `rel="noopener noreferrer"` が付くため、ブラウザは参照元のページを伝えず、LinkedIn のスクリプトや API は読み込まれることも呼び出されることもありません。
- **クリックが記録する内容**: 最初のクリックは、公開プロシージャ `certificate.recordLinkedInClick({ certificateId, source })` を呼び出し、修了証の `linkedInClickedAt` と `linkedInClickSource` を一度だけ設定します。以後は変更されません。記録に失敗しても、フォームが開かなくなることはありません。この記録が意味するのは「受講生がフォームを開いた」ことであり、「修了証が LinkedIn にある」ことではありません。LinkedIn は何も返してきません。
- **クリックの発生元**: `linkedInClickSource` は `my-learning`、`certificate-page`、`issued-email`、`reminder-email` のいずれかです。2通のメールは `/certificates/<ID>/linkedin?source=…` にリンクします。このポータルのルートはサインアウト状態でも動作し、利用を記録して、ページを LinkedIn のアドレスに置き換えます。
- **利用状況の読み方**: `linkedInClickedAt` を持つ修了証の割合を、`linkedInClickSource` ごとに分けたもの。この数値は保存されたレコードから導かれます。
- **LinkedIn が値を無視する場合**: リンクは引き続き正しいフォームを開き、公開ページの所有者向けの表示には、手作業でコピーするためにすべての値が一覧されます。LinkedIn 自身のヘルプには、カスタマイズしたリンクで自動入力されない場合があると書かれています。メンテナーが 2026-11-20 に、フォームが値付きで開くことを確認しました（spec の research R-1 から R-3）。

## 受講生への通知

- **通知** `certificate.issued` は、`issueCertificate` によって修了証と同じトランザクションで、修了証 ID を重複排除キーにして書き込まれます。そのため、通知のない修了証が存在することはなく、再試行しても2つ目の通知は作られません。
- **メール**には2つのリンクがあります。修了証のページと、**Add to LinkedIn profile**（通知の任意の `action` で、ベルでは無視されます）です。
- **設定**: 通知設定の **Certificates** という1つのスイッチが、発行メールとリマインダーの両方を制御します。`certificate.reminder` に独自の設定はなく（`emailPreferenceType` は `certificate.issued` を指します）、最初のメールの配信を停止すると、リマインダーも止まります。
- **リマインダー**: 発行の3日後に、1回限りの EventBridge Scheduler のスケジュール（`cert-reminder-<ID>`）が `certificate-reminder` Lambda を呼び出します。メールの種類がオフの場合は止まります。そうでなければ、クリックが記録されておらず、リマインダーも送信されていない場合にだけ成功する、`reminderSentAt` の条件付き書き込みでリマインダーを確保し、保存された時刻とともに `certificate.reminder` を発行します。クリックと送信は互いに安全で、先に書き込まれたほうが決定します。発行されたもののスケジュールされなかった修了証は、後の再計算で修復されますが、リマインダーがすでに期限を過ぎている場合は除きます。リマインダーが遅れて送られることはありません（research R-4 から R-7）。

## リンクプレビュー

リンクプレビューのクローラーはスクリプトを実行しないため、ページレンダラー（<Link path="design/public-pages">公開ページ</Link>を参照）は、`certificate.verify` から作った head で `/certificates/<ID>` に応答します。内容は、「the learner completed the course」というタイトル、修了日、プラットフォーム名、ID です。ページが表示する以上の内容が出ることはありません。このページは人物の名前を含むため、どのステージでも常に `noindex` です。`/certificates/<ID>/linkedin` のようなより深いパスには、通常のテンプレートが使われます（research R-8）。

## 制限事項

- 基準には履歴がありません。修了証が発行された時点のバージョンと設定だけが、修了証に保持されます。
- クイズは、そのクイズ自身の合格点で評価されます。コース全体の合格点や、何を対象にするかをクイズごとに選ぶ機能はありません。
- すでにダウンロードされた、取り消し済みの PDF は残ります。無効になったことを示すのはページだけです。
- LinkedIn は何も返さないため、Discava には、修了証がプロフィールに保存されたかどうかはわからず、フォームが開かれたことだけがわかります。
- 修了証 ID を持っていれば誰でも、最初の利用を記録できます。その影響は、リマインダーが1通減るだけです。
- PDF は標準フォントを使うため、Latin-1 の範囲外の文字（たとえば中国語、日本語、絵文字）は `?` と印刷されます。公開ページでは正しく表示されます。
