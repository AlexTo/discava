## 誰が何をできるか

アクセスは層ごとに判断され、各層は、その前の層が破られる可能性を前提にしています。

| 層 | 強制する内容 |
| --- | --- |
| **Cognito グループ** | ユーザーのロール: `student`、`instructor`、`admin` |
| **分離された API** | 講師向けと管理者向けのプロシージャは、別々のデプロイです。受講生のトークンは、どのプロシージャも実行される前に instructor-api に拒否されます |
| **プロシージャのルール** | 個別のルール。この講師がこのコースを所有している、この受講生がこのコースに登録している、など |
| **署名付きメディア** | 動画やファイルは、そのために署名されたリクエストにだけ配信されます。署名は、登録などのアクセス確認の後に発行されます |

下書きやアーカイブ済みのコースは、見るべきでない人には「見つかりません」と応答するため、その存在も明かされません。

## ステージごとの保護

すべての保護は**既定でオン**です。ステージの設定でできるのは無効にすることだけで、`discava-development` は費用を抑えるためにそうしています。

| 保護 | 内容 | 本番 | 開発 |
| --- | --- | --- | --- |
| **WAF** | ポータル、API、メディア、ユーザープールの Web アプリケーションファイアウォール | オン | オフ |
| **KMS 暗号化** | テーブル、バケット、キュー、ログ、検索に対する、ローテーション付きのカスタマー管理キー | オン | オフ（AWS 管理の暗号化） |
| **MFA** | サインイン時の第2要素 | オン | オフ |
| **削除保護** | ユーザープールとテーブルの削除を拒否する | オン | オフ |
| **削除時に保持** | スタックを削除してもデータを残す | オン | オフ |
| **セルフサインアップ** | 誰でもアカウントを作成できる | オン | オフ |
| **トレーシング** | X-Ray によるリクエストのトレーシング | オン | オフ |

データは、保存時も転送時も常に暗号化されます。KMS の設定は、そのキーを自分で管理・監査できるかどうかを決めます。

WAF をオフにした開発ステージでは、ステージの設定にあるリクエスト制限、関数の同時実行数、テーブルのスループット上限が、リクエストの急増による費用を抑えます。セルフサインアップがオフなら、部外者がアカウントを得て、サインインが必要なプロシージャに到達することはできません。

## システム内の最小権限

- 各 Lambda 関数には専用のロールがあり、その仕事に必要な権限だけを持ちます。
- 機微な機能は専用の関数に隔離されています。レッスンメディアのリクエストに署名するキーは、core-api の1つの関数と instructor-api の1つの関数だけが読め、他のすべてのプロシージャを処理する関数は読めません。
- Stripe のキーと webhook 署名シークレットは Secrets Manager にあります。書き込めるのは admin-api の1つの関数だけです。チェックアウト、webhook、支払いアカウント、支払い処理の関数は、必要なものだけを読み取り、どのレスポンス、ログ行、監査記録にも、どちらも含まれません。
- Stripe webhook は、保存された署名シークレットに対して署名が検証できたメッセージだけを受け付けます。支払いをブラウザーからの情報で信用することはありません。
- 公開されている S3 バケットはありません。ポータルとメディアには、CloudFront ディストリビューション経由でしか到達できません。
- ページレンダラーは、テーブルへの読み取り専用のアクセスで公開ページを提供し、呼び出せるのは受講生ポータルの CloudFront ディストリビューションだけです。
- 各 API は、それを呼び出すポータルからのクロスオリジンリクエストにだけ応答します。core-api は3つすべて、instructor-api は講師ポータル、admin-api は管理ポータルです。ローカル開発のアドレスも許可されています。
- 検索インデックスに書き込めるのは、インデックス用の関数だけです。API は読み取りしかできません。
- 関数は、デプロイ時の環境変数からリソース名を得ます。認証情報がコードや環境ファイルに現れることはありません。

## コードをデプロイする前のチェック

| チェック | 場所 | 検出するもの |
| --- | --- | --- |
| **Checkov** | すべてのビルド | 生成されたテンプレート内の、安全でないインフラ設定 |
| **Trivy** | CI と、各デプロイの前 | 依存関係の既知の脆弱性と、コミットされたシークレット |
| **git-secrets** | 各コミットの前 | コミットされようとしている認証情報 |
| **テーブルの不変条件** | エンドツーエンドテスト | 複数のレコードにまたがるルールを破る状態で残ったデータ |

## デプロイを範囲内に収める

デプロイパイプライン自体が攻撃対象になるため、次のように制約しています。

- **AWS の認証情報を保存しません。** GitHub Actions は、1回の実行のために発行されたトークンでサインインします。
- **デプロイロールは、1つのリポジトリの1つの environment だけを信頼します。** その environment を必須レビュアーで保護すれば、デプロイの関門になります。
- **デプロイロールはリソースを作成できません。** 自分のステージ名が付いたスタックのデプロイを CloudFormation に依頼できるだけです。
- **実行ロールは**、ステージのリソースに名前で限定されています。
- **Permissions boundary** が、ステージが作成するすべてのロールに上限を設けるため、デプロイされた変更が boundary を超える権限を自分に与えることはできません。

サインインと2つのロールについては、<Link path="deploy/ci-cd">CI/CD リファレンス</Link> で説明しています。

## 脆弱性の報告

公開の issue は開かないでください。[CONTRIBUTING.md](https://github.com/AlexTo/discava/blob/main/CONTRIBUTING.md#security-issue-notifications) のセキュリティ通知の手順に従ってください。
