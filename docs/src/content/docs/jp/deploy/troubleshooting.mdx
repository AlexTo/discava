## セットアップスクリプト

**"Couldn't authenticate with AWS."** AWS CLI に有効な認証情報がありません。サインインして（`aws sso login --profile <profile>` または `aws configure`）、スクリプトをもう一度実行してください。

**"`<stage>` is configured for account … ; switch credentials and re-run."** `stages.config.ts` でステージにアカウントが指定されているのに、別のアカウントにサインインしています。

**"Unknown stage."** ステージが `stages.config.ts` にありません。先にそこへ追加してください。

**"The origin remote isn't a GitHub repository."** `--yes` を付けたときに表示されます。付けない場合、スクリプトはリポジトリを尋ねます。自分で指定してください: `GITHUB_REPOSITORY=<you>/discava ./scripts/setup-stage.sh`。

**"stdin isn't a terminal."** スクリプトが質問できません。ターミナルで実行するか、`--yes` を付けて既定値を受け入れてください。

**"uses a custom OIDC subject claim template."** リポジトリまたは組織が OIDC トークンのサブジェクトをカスタマイズしています。サブジェクトのうち `:environment:` より前の部分を `GITHUB_OIDC_SUBJECT_PREFIX` に設定して、スクリプトをもう一度実行してください。

**"no issued certificate in … covers …" または "… is for exactly …"** ルートドメインを使う場合、スクリプトはすべてのコンポーネントに発行済みの証明書を必要とします。見つからなかったものをすべて一覧にして、何も変更する前に止まります。メッセージが示すリージョンの ACM で証明書をリクエストしてください。2つの API はステージのリージョン、ポータルとメディアは `us-east-1` です。それぞれが **Issued** になるまで待ってから、スクリプトをもう一度実行します。各 API には、自分のドメイン（`core-api.<root>`、`instructor-api.<root>`）だけを正確に指す証明書が必要で、ワイルドカードは使えません。ポータルとメディアは、`<root>` と `*.<root>` の1つの証明書を共有できます。カスタムドメインなしでデプロイするには、ルートドメインを空欄にしてください。

## Deploy ワークフロー

**`main` へのプッシュ後にワークフローが始まらない。** 自動デプロイには3つのものが必要です。リポジトリ変数 `AUTO_DEPLOY_STAGE`、フォークで有効になっているワークフロー、そして**成功した** CI 実行です。CI の実行を確認してください。**Deploy Docs** ジョブ（GitHub Pages が有効でない）や **Trivy** ジョブが失敗すると、CI 全体が失敗になります。

**"Unknown stage".** 入力したステージが、デプロイ対象のコミットの `stages.config.ts` にありません。

**"Not authorized to perform sts:AssumeRoleWithWebIdentity".** AWS がワークフローのトークンを拒否しました。よくある原因は次のとおりです。

- GitHub environment の名前が、ステージ名と完全に一致していない
- セットアップスクリプトを別のリポジトリのクローン（フォークではなく元のリポジトリ）から実行したため、ロールがそちらを信頼している
- セットアップ後にフォークの名前を変更した、または移管した

ワークフローを実行するリポジトリのクローンから、セットアップスクリプトをもう一度実行してください。

**"Credentials could not be loaded" または空のロール。** environment に `AWS_DEPLOY_ROLE_ARN` 変数がありません。セットアップスクリプトを実行するか、表示された変数を作成してください。

**"Invalid value for `<STAGE>_INFRA_…`".** 設定の上書きに、種類の違う値が入っています。真偽値は `true` か `false`、数値は整数、ログレベルは `DEBUG`、`INFO`、`WARN`、`ERROR` のいずれかです。GitHub environment の変数を直して、もう一度デプロイしてください。

**"SSM parameter /cdk-bootstrap/hnb659fds/version not found".** ステージがデプロイするリージョンで CDK がブートストラップされていません。セットアップスクリプトをもう一度実行してブートストラップを受け入れてください。WAF を使うステージでは `us-east-1` も忘れずに。

**CloudFormation がリソースを作成中にアクセス拒否される。** CloudFormation は実行ロール `cfn-execution-<stage>` として動きます。このロールは Discava が作成するものだけを、ステージ名で始まる名前のリソース（`discava-development-…`、種類によっては `discavadevelopment…`）に対してのみ行えます。

新しいバージョンの Discava を取り込んだばかりなら、まずセットアップスクリプトをもう一度実行してください。そのバージョンに必要な権限にロールが更新されます。それでもエラーが残る場合や、自分でリソースを追加した場合は、エラーが名指ししている対象を見てください。

- **`cfn-execution-<stage>` が拒否された場合。** `scripts/setup-stage.sh` の実行ロールのポリシーに、そのアクションを追加します。リソースの名前がステージ名で始まらない場合は、代わりにステージ名で始まる明示的な名前を付けてください。CDK の `Names.uniqueResourceName` が、コンストラクトのパスから名前を作ります。その後でスクリプトを再実行します。
- **関数の実行時に、その関数のロールが拒否された場合。** 同じスクリプトの permissions boundary にそのアクションを追加し、もう一度実行します。ステージが作成するすべてのロールにこの boundary が付いています。実行ロールには付いていないので、boundary にアクションを追加してもデプロイは直りません。

自分のマシンからのデプロイでは、何でもできる CDK の既定のロールを使います。そのため、ローカルでデプロイできるスタックが、Deploy ワークフローでは失敗することがあります。

**Trivy のステップが失敗する。** 修正が利用できる重大な既知の脆弱性が依存関係にあるか、シークレットがコミットされています。依存関係を更新してください。確認して受け入れた検出結果は、`.trivyignore` に1行1 ID で追加します。

**スタックが `ROLLBACK_COMPLETE` のまま動かない。** 最初の作成で失敗したスタックは更新できません。CloudFormation コンソールで削除して、もう一度デプロイしてください。

## デプロイ後

**ポータルにサインインエラーが出る。** ユーザーが、そのポータルに必要なグループ（`student`、`instructor`、`admin`）に入っているか確認してください。

**カスタムドメインが名前解決されない。** DNS レコードは自動では作成されません。ドメインを CloudFront ディストリビューションまたは API Gateway のカスタムドメインに向けてください。

**ポータルのドメインを追加した後、API 呼び出しが CORS エラーで失敗する。** もう一度デプロイしてください。API が許可するオリジンは、デプロイ時にポータルのドメインから取得されます。

**最初の検索が遅い。** `discava-development` では、検索がゼロまでスケールダウンします。しばらく使われなかった後の最初のクエリは、容量の確保に10〜30秒待ちます。

**メールが届かない。** 2つの `NOTIFICATIONS` 変数が設定されているか、SES の ID がステージのリージョンで検証されているか、SES アカウントがまだサンドボックスにないかを確認してください。

**動画が "processing" のままになる。** ステージのリージョンの MediaConvert コンソールで、ジョブ一覧から失敗したジョブとそのエラーを確認してください。
