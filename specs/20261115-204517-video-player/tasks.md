# Tasks: Video Player Upgrades

**Input**: Design documents from `/specs/20261115-204517-video-player/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: The Discava constitution (principle IV) requires them, so they are included: unit tests for each procedure, helper and handler; component tests for the player controls; an invariant check, with a test that breaks it, for each rule that spans records (impact check in plan.md); and `packages/e2e` scenarios. Write each phase's tests first and see them fail. Never weaken an existing test to make it pass (constitution IV). The one deliberate behavior change to existing tests is named in T004 (native controls replaced); the PR description must say so.

**Who runs what**: an automated agent implements these tasks without `pnpm dev` or Docker. It runs unit and component tests, lint, typecheck, `build` and `synth` locally. The e2e scenarios and the concurrency test are written by the agent but run on PR CI (`pr-checks.yml`'s `E2E tests` job); a CI failure is the feedback for those. Tasks marked **(human)** need a running local stack, a deployed stage or people, and are done by a reviewer before merging.

**Organization**: each phase is one pull request, in order (a later phase builds on the earlier ones), with a few tasks each. Paths are relative to the repository root. Story labels: US1 resume (P1), US2 speed, volume and shortcuts (P1), US3 read along with captions (P1), US4 auto-generated captions (P2), US5 instructor captions (P2).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: the user story the task serves

**Merge order and independence**: Phase 1 has no backend and can ship alone. Phase 2 needs Phase 1's player. Phase 3 needs Phase 1 and ships captions delivery with no tracks yet. Phase 4 and Phase 5 together make captions appear on deployed stages: Phase 4 alone is safe (a Transcribe start that fails, for lack of the audio file or permissions, only sets `captionsStatus: failed`, never blocking a video), but merge Phase 5 promptly after. Phase 6 needs Phase 3. Phase 7 is last.
