# Tasks: Coupons and Discount Codes

**Input**: Design documents from `/specs/20261116-013138-coupons-discount-codes/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md). **#284 (Stripe checkout) must have merged its order entity and course price before PR 1 starts** (plan R1); its spec was not available when this one was written.

**Tests**: The Discava constitution (principle IV) requires them, so they are included: unit tests for the price function, code helpers, the claim, confirm and release builders, each procedure and each component; invariant checks with tests that break them; a `packages/e2e` scenario and a concurrency test. Write each phase's tests first and see them fail. Never weaken an existing test to make it pass (constitution IV).

**Who runs what**: an automated agent implements these tasks without `pnpm dev` or Docker. It runs unit and component tests, lint, typecheck, `build` and `synth` locally. The e2e scenario and concurrency test are written by the agent but run on PR CI (`pr-checks.yml`'s `E2E tests` job). Tasks marked **(human)** need a running local stack, Stripe test mode or people, and are done by a reviewer before merging.

**Organization**: Six phases, each one agent PR, merged in order (each phase leaves `main` green and working: no phase needs a later one to pass). Story labels: US1 instructor creates codes (P1), US2 student applies a code and pays (P1), US3 free path (P1), US4 usage limit under concurrency (P1), US5 instructor manages codes (P2). Paths are relative to the repository root. Only the last PR closes #285; earlier PRs say "Part of #285" and must not use a closing keyword.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
