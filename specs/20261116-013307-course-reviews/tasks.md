# Tasks: Course Ratings and Written Reviews

**Input**: Design documents from `/specs/20261116-013307-course-reviews/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: The Discava constitution (principle IV) requires them, so they are included: unit tests for the helper, rating arithmetic, each procedure, the search document and the indexer; invariant checks with tests that break them; portal component tests; a `packages/e2e` scenario and a concurrency test. Write each phase's tests first and see them fail. Never weaken an existing test to make it pass (constitution IV); where a task changes an existing assertion on purpose, it says which behavior changed and the PR description repeats it.

**Who runs what**: an automated agent implements these tasks without `pnpm dev` or Docker. It runs unit and component tests, lint, typecheck, `build` and `synth` locally. The e2e scenario and concurrency test are written by the agent but run on PR CI (`pr-checks.yml`'s `E2E tests` job). Tasks marked **(human)** need a running local stack or people, and are done by a reviewer before merging.

**Organization**: Eight phases, each one agent PR, merged in order (each phase leaves `main` green and working: no phase needs a later one to pass). Story labels: US1 post and manage a review (P1), US2 see ratings (P1), US3 instructor responses (P2), US4 admin removal (P2), US5 instructor notifications (P3). Paths are relative to the repository root. Only the last PR closes #279; earlier PRs say "Part of #279" and must not use a closing keyword.

**Cross-feature order**: the admin API (Phase 6) is shared with the catalogue categories spec (#333), the search document and `course.publicSearch` (Phase 4) are also changed by #333, and Phase 7 needs the notifications spec (#331). Each such task begins by checking `main` for the other feature and either reuses what is there or creates it (the task says how); none blocks the other feature from merging first.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
