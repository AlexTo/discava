# Tasks: Admin-Set Platform Branding

**Input**: Design documents from `/specs/20261122-090054-admin-branding/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: The Discava constitution (principle IV) requires them, so they are included: unit tests for `@discava/common-branding`, the core-table helper, each admin-api procedure, the publishing handler, the page renderer, `BrandProvider` and the admin portal page; one new invariant with breaking tests; a `packages/e2e` scenario and a concurrency test. Write each task's tests first and see them fail. Never weaken an existing test to make it pass; where a task changes behaviour an existing test pins (the `Discava` site name in page-renderer tests, `app-config` in shell tests), the task names the change and the PR description says so.

**Who runs what**: an automated agent implements these tasks without `pnpm dev` or Docker. It runs unit and component tests, lint, typecheck, `build` and `synth` locally. Whenever a task changes which code writes the core table, it also runs `pnpm nx run @discava/tooling-agent:entity-writers` and commits the regenerated `packages/databases/core-table/entity-writers.json`, or the `Invariant coverage` PR check fails. The e2e scenario and concurrency test are written by the agent but run on PR CI (`pr-checks.yml`'s `E2E tests` job). Tasks marked **(human)** need a running local stack, a deployed stage or people, and are done by a reviewer before merging.

**Organization**: Seven phases, each one agent PR merged in order; each leaves `main` green and working. Story labels: US1 logo and icon (P1), US2 platform name and share image (P2), US3 brand colour (P3), US4 reset to default (P3). Paths are relative to the repository root. There is no tracking issue yet; open one before Phase 1 and reference it as "Part of #<n>" in every PR, with only the last PR closing it.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: which user story the task serves (US1 to US4)
- **(human)**: needs a running local stack, a deployed stage or people; not done by the agent
